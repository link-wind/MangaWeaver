# 消息、引用与专业交接验收

日期：2026-10-31。OpenSpec：`refine-agent-messages-and-handoffs`。

本轮实现消息分流、固定画布引用和专业任务书／回报。沿用三阶段制作、现有 Creator／Reviewer、检查点和文件式恢复，未修改供应商、模型、分辨率或 H3 能力限制。

## 验证方法

- Python 共 37 项检查，包含 5 项新的消息／引用边界检查；扩展已有 GPT Image 本地 HTTP 检查，核对参考图字节、任务要求实际传输及输入变化阻止旧缓存复用。
- 桌面原有 14 项检查、TypeScript／Vite／esbuild 构建和 OpenSpec 严格校验。
- 使用真正的 Electron 客户端，通过原生应用接口点击、输入、选择、停止和恢复。测试项目为 `results/agent-messages-validation-20261031/project/`，使用独立 user-data 目录；用户正常客户端配置没有改为测试解释器。
- 专业模型和总 Agent 在测试解释器中返回明确标注的本地协议预设，生成任务书、候选、审查和交接记录；正式代码未加入测试供应商。预设不调用真实模型，不生成付费图片或视频，不代表动画效果。

## 客户端及接口检查

| 功能 | 验证内容 |
| --- | --- |
| 加入选中项 | 点击整页节点并加入输入框，出现目标标签及真实版本引用 |
| 本地进度查询 | 运行中发送“现在做到哪了？”，立即出现已回答结果，未创建修订或调用模型 |
| 快速收件归属 | 修正新任务事件尚未到达时误绑上一任务的问题，由引擎核对本页实际活动任务；客户端复查指向当前编排 |
| 后续要求 | 从送达菜单选择稍后处理，当前编排继续，完成后创建独立后续任务并记录来源要求 |
| 撤回 | 运行中排队后从消息记录撤回，记录变为已撤回，不再启动 |
| 停止 | 运行中输入单独“停止”，本地子进程退出，父子任务中断，后续要求继续保留待处理 |
| 重开 | 重开项目恢复中断和待处理记录，没有自动运行 |
| 显式恢复 | 点击原任务恢复，继续原身份与检查点，完成后才处理已排队后续要求；已撤回要求保持撤回 |
| 专业交接 | 原阶段流水线记录 Creator 提交、Reviewer 拒绝及依据、交给对应 Creator、下一轮提交和通过；任务书、回报与真实文件关联 |
| 引用实际传输 | 本地 HTTP 接口收到参考图和任务要求；改变任务要求后原图片缓存拒绝复用，没有重复提交 |
| 引用失效 | 覆盖参考内容后校验报错，未改用新文件；项目外运行被拒绝 |
| 当前问题 | 普通问题回答后保留任务状态；目标含糊时等待决定，不默认编排或全部镜头 |
| 运行中局部修改 | 客户端发送第二镜头修改，检查点后创建修订运行，专业审查通过后显示已应用及继续原制作入口；任务书目标为 `s002` |

运行中的临时脚本检查点可能暂未发布镜头。修订目标因此优先结合发送时上下文、当前已发布对象及任务书绑定的未变化输入版本解析，避免将原本存在的镜头错误地判为缺失。早期失败记录留在本地测试项目，没有改成成功记录。

## 实施边界

- 引用以现有运行与内容签名保存，缺失或被覆盖时明确重选，不增加完整素材快照库或自动依赖传播。
- 当前只接入图像／结构化参考的制作输入；视频可查看，不能把视频引用等同于 H3 生成控制能力。
- 后续要求仍受明确目标与授权限制，阶段失败、暂停或停止不会触发自动出队；重开仅恢复显示。
- 不把本地协议预设、请求传递或审查事件检查当作真实模型效果验收。没有新增付费模型测试，也没有验证 Lite／480P。
- 构建仍有现有的大文件体积提示，macOS 安装包继续使用开发签名设置。
