# Agent 会话客户端验收（2026-11-01）

## 环境与范围

使用打包后的原生 `MangaWeaver.app`，通过应用操作接口点击打开项目、输入、运行、停止和分支菜单。实际配置为幻灵 `gemini-3.8-flash`、native、curl；密钥仅从本地环境读取。没有更换模型，没有调用付费生图或视频。

测试项目：`results/agent-runtime-validation-20261101/project`。其中 `dialogue` 用于六格来源的中断验证，`single-panel` 用于最小专业链路，`question` 用于要求先提问的专业链路。测试来源引用既有漫画素材，产物写入隔离运行；没有覆盖原成片。

## 真实渠道及客户端结果

| 检查 | 结果 |
| --- | --- |
| 当前模型真实 SSE | 最小正文请求首段约 11.9 秒到达，随后多个增量及 STOP；结构化 AgentAction 检查收到 4 段公开文字，最终通过 Schema 校验 |
| 右栏文字与专业调用 | 原生客户端显示实际文字、独立 Creator／Reviewer 以及工具终态；最终内容与日志一致 |
| 停止与重开 | 客户端停止六格专业 Creator；部分文字保留，父子状态中断，重新打开没有自动重跑 |
| 最小专业链路 | 在客户端点击来源脚本阶段，单格 Creator 提交后，角色 Reviewer 和 p001 Reviewer 均完成并通过原审查 |
| 后续要求 | 制作期间用“稍后处理”排队，只在脚本成功后独立回复“脚本验收结束”；没有继续编排或生图 |
| 编辑与分支 | 编辑历史要求并发送，创建“方案 1”，得到“分支测试通过”；切回主对话恢复原记录与产物，没有重放制作 |
| 上下文压缩 | 客户端手动点击压缩，实际文本模型返回结构化摘要，界面估算由约 4.5k 变为约 3k；原 5 条消息仍保留 |
| 专业提问与回答 | Creator 实际返回“这次背景采用浅蓝色吗？”，阶段暂停；重开后直接显示问题卡片，输入确认后送回原子会话；Creator 继续提交，两个 Reviewer 完成并通过 |

本轮共记录 8 个轮次、2 个对话分支及 7 个实际专业会话记录（其中一个中断，其余完成）。回答前后的 Creator 会话身份保持一致，行动数从 1 增到 2，历史中保存了确切问题和回答。最终 pending 为空。上述数量由本轮隔离项目提取，不表示原制作算法或所有供应商都完成了全链路验证。

结构化证据：`docs/validation/agent-stream-provider-2026-11-01.json`、`docs/validation/agent-runtime-client-2026-11-01.json`。原始过程留在测试项目的 `conversation.jsonl`、`agent_sessions/`、`tasks.json` 及原专业产物中。

## 验收发现与修正

- 新轮次开始时立即显示用户消息，避免等待模型完成才看到自己的输入。
- 不把项目旧 goal 当作本轮新要求；解释性问题优先直接回答。
- 专业问题直接显示，避免藏在折叠详情里；回答也保存到公开对话和原子会话。
- 处理专业 JSON 包装导致的公开文字未增量解析情况：最终校验后补齐确切文字，不模拟流式、不提前执行。
- 专业会话按角色、模板、目标及输入基线隔离，逐格 Reviewer 不混用会话。
- 增量事件按持久身份去重；工具关联的任务详情收进对应工具块。
- 上下文详情改为紧凑弹层；纯压缩事件不产生空回复气泡。
