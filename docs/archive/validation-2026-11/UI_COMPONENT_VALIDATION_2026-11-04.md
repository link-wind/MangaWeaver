## 修复的问题

1. 规划版本原先把展示名称作为值，无法可靠匹配文件；现使用真实文件名。
2. 官方 Dialog 默认最大宽度压缩设置页；为设置、选材、引用及清理确认提供明确的响应式尺寸。
3. 迁移后的媒体播放按钮失去覆盖定位；恢复为共享 Button 的覆盖式操作。
4. 多行镜头条目被默认按钮高度挤压；改用内容自适应高度与换行。
5. 对话输入边距叠加百分比宽度造成溢出；明确扣除左右边距。
6. 最小窗口的对话历史与目录出现横向滚动；限制水平溢出并去掉消息额外的左外边距。

### 三栏拖动反馈复查

drag 复现时临时监听确认：当前电脑操作接口只向页面发出一次 `pointerdown` 和一次 `pointerup`，中间没有 `pointermove`；分栏库没有错误地自动取消一个完整的连续鼠标手势。不能据此宣称鼠标拖动已通过。

代码检查发现两个确定问题并已修复：

- `onResize` 把实时宽度写回父组件，再作为变化的 `defaultSize` 传给 `react-resizable-panels@4.18.0`。v4 会在默认尺寸变化时注销并重新注册 Panel，可能打断正在进行的拖动。共用 `ResizablePanel` 现在在每次挂载时固定初始默认宽度；实时值仍保存，关闭再打开右栏时能读取最新宽度。
- 目录收起时，64px 临时宽度可能覆盖保存的展开宽度。现在改用分栏库自身的 `collapse()`／`expand()`，由它保存展开前尺寸；收起过渡不写入宽度偏好。

最终独立客户端再次验证目录收起／展开、宽度调整与 Home 复位，以及右侧对话栏调整、Home 复位、收起／展开恢复宽度。目录从 22.982% 收起后再展开仍为 22.982%；没有调用模型或执行生成。连续鼠标拖动因操作接口事件不足，仍保留为待人工验收项，不能把键盘调整当作拖动通过。
