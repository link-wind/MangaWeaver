# MangaWeaver 界面修改方案

日期：2026-11-01  
状态：已按 OpenSpec `clarify-workbench-task-context` 实施，验收见文末。  
范围：覆盖 Impeccable 评审的五项优先问题，先解决任务与操作理解，再处理阅读和视觉细节。

## 1. 修改目标

让用户在画布中直接看清三件事：**正在操作谁、已经做到哪一步、接下来会执行什么。**

继续采用白色、简约的三栏工作台，保留可调整的目录／画布／对话区域、无阴影分隔线、单击选择与双击详情。首页保留漫画输入与 prompt，列表继续只显示已有成片。

沿用现有创作 Agent、Creator／Reviewer、三阶段引擎和文件产物。本轮以展示与交互调整为主，不增加 Agent、服务、数据库、模型调用、回退框架或重复确认弹窗。

依据：[Impeccable 评审记录](../.impeccable/critique/2026-11-01T09-45-43Z__desktop-src-app-tsx.md)。该评审为只读界面检查，26/40 的评分不代表完整生成链路验收。

## 2. 修改范围与优先级

| 顺序 | 问题 | 修改结果 |
|---|---|---|
| 1 · P1 | 当前页与历史任务容易混淆 | 每张制作任务卡明确显示真实来源页或运行归属 |
| 2 · P2 | 制作、节点操作、对话权限含义相近 | 清楚区分连续制作、单阶段执行和对话授权 |
| 3 · P2 | 协作摘要与审查依据重复 | 默认短结论，展开查看真实角色过程和审查依据 |
| 4 · P2 | 小字偏浅，菜单键盘行为不完整 | 提高可读性，统一 Escape、焦点和中文标注 |
| 5 · P2 | “项目库”实际只展示成片 | 改称“成片库”，提供直接继续当前项目的入口 |

作品显示名、原稿重复展示、大图详情增量信息和提示横条占用空间作为后续事项，本轮不扩展实施范围。

## 3. 任务归属与当前进度

### 3.1 区分项目对话与操作目标

右栏仍为项目级对话，切换漫画页不丢失历史，也不重新创建会话。“当前第 N 页”表示当前操作上下文，不能让全部历史回复看起来都属于该页。

页码和目标放在具体操作区域；历史制作任务各自标注归属。普通聊天回复不强行追加页码。

### 3.2 任务卡显示真实来源

制作任务卡默认显示：

- 来源：文件第 N 页，或独立运行。
- 阶段与状态：例如“来源脚本 · 已通过”。
- 真实协作角色及简短结论。
- 原有定位、恢复等可用操作。

归属优先使用任务的 `run`、`page_id` 和项目已有的书籍／运行映射。节点引用继续使用已有目标及来源签名。

无法核实页码时显示“历史运行”或已有运行名称，不能套用当前页码，也不能因缺少页码隐藏任务。多个来源页只能展示已有数据能证明的关系。

### 3.3 示例

当前操作文件第 12 页时，历史任务可以呈现为：

| 任务归属 | 阶段 | 结论 |
|---|---|---|
| 文件第 10 页 | 来源脚本 | 已通过 |
| 文件第 12 页 | 漫画分格 | 待处理 |
| 独立运行 | 视频成片 | 已中断，可恢复 |

以上仅为文案示意。实际状态、页码及恢复操作全部取自真实记录，不预建未运行阶段的完成卡片。

“查看画布”继续定位到对应任务和对象，不把目标悄悄改成当前选中页。

## 4. 统一制作入口

### 4.1 三种操作的职责

| 入口 | 对象与行为 | 展示规则 |
|---|---|---|
| 画布顶部 | 当前运行或明确勾选的多个运行，连续执行至选择的终点 | 显示当前范围与终点；主按钮改为“开始制作”，运行中为“停止” |
| 节点快捷操作 | 对应运行的一个阶段 | 悬停或聚焦显示，提示“仅执行漫画分格”等具体阶段 |
| 对话输入框 | 当前对话目标和显式引用，由创作 Agent 理解要求 | 显示目标；发送旁的选项表达允许调用的能力 |

顶部继续使用已有 `until`，节点继续使用已有单阶段执行。停止、中断、恢复和后端权限检查沿用原机制。

### 4.2 减少“制作范围”的歧义

顶部选择的是**本次制作终点**；输入框选择的是**对话可用权限**。两者不能使用看起来完全相同的表达，使用户误以为会自动同步。

输入框选项建议为：

| 显示文案 | 沿用的值 |
|---|---|
| 仅对话 | `none` |
| 可规划 | `planning` |
| 可规划与生图 | `images` |
| 可完整制作 | `video` |

默认仍为“仅对话”。用简短 tooltip／可访问名称解释“允许对话调用哪些制作能力”，不增加常驻说明段落，不修改既有授权取值或自动扩大权限。

顶部操作沿用自身已有授权流程，不能从聊天菜单推断出新的授权；发生需要用户处理的问题时继续通过原有问询呈现。

### 4.3 选择与引用

单击节点改变选择，双击打开详情；顶部勾选的批量运行范围继续独立显示。选择节点不会悄悄改变批量选择。

输入框保留“目标／参考”用途区分。跨页或独立运行的目标应有来源提示，避免所有对象都只显示“整页漫画”。草稿、引用、运行中消息送达方式继续保留。

## 5. 精简多 Agent 协作展示

### 5.1 默认任务卡

默认只保留归属、阶段、状态、简短结论和真实角色关系。例如：

“文件第 12 页 · 镜头编排”  
“编排创作 → 编排审查”  
“需要修订 · 2 项问题”

问题数量只在当前对象、当前轮次的数据可明确计算时显示。没有明确审查结果时，不能写“通过”；没有问题计数时，不补成“0 项问题”。

优先使用已有结构化状态、审查结论和问题列表；不新增模型请求生成摘要。旧自由文本可以限制默认显示行数，完整内容必须可展开查看。

### 5.2 展开的协作过程

按已有事实展示角色、轮次、结论、反馈与产物定位。让用户能读懂“谁提出了什么、谁退回了什么、修订后是否通过”。

默认摘要负责结论，展开内容负责依据，避免将同一长句重复显示。历史任务默认收起，保留用户的展开状态；查看新事件不抢走正在阅读的位置。

技术详情继续保留原始参数、任务和事件。确定性工具仍作为工具显示，不包装为新的 Agent，也不生成虚构互聊。

### 5.3 问题与异常

待回答问题、需要修订的明确结论和原有恢复按钮保持可见，不藏在技术详情里。完整错误保留，默认使用可理解的短说明。

界面只描述已知状态；“进度已保留”不能被表达成远端视频也已停止。内容审查中的时长问题与网络请求超时继续区分。

## 6. 可读性与键盘操作

- 保留白底和少量紫色强调，提高辅助文字、完成状态、快捷键提示的对比度；通过文字和图标共同表达状态。
- 小字号正文按普通文本对比度目标检查，不通过把文字变得更浅来降低信息密度。
- 更多菜单与引用菜单支持 Escape 关闭，并将焦点返回触发入口；点击外部关闭行为保持一致。
- 创作／详情标签支持符合标签页语义的键盘切换与清楚焦点，避免焦点落入隐藏面板。
- 缩放控件统一为“放大／缩小／适应画布”，保留可访问名称。
- 小图标维持简洁视觉，按实际需要扩大命中区；不机械把桌面所有控件改为大尺寸触控按钮。
- 检查实际窗口、窄窗口及放大状态的布局和文字。视觉对比度按实际生效的颜色验证，不能把源码扫描零命中当成合规结论。

不增加阴影、背景装饰、常驻帮助面板或强制新手教程。必要解释优先放在控件名称、tooltip 和有上下文的空状态中。

## 7. 成片库与继续创作

全局“项目库”改称“成片库”，页面标题、导航、搜索和空状态同步表达“成片”。继续只列已有最终视频或预览视频的记录，不混入规划草稿、关键画面或模拟结果。

已有项目时，首页“继续当前项目”直接返回已打开项目的画布和上下文，不要求再次选择文件夹；未打开项目时提供“打开项目”。

项目名菜单继续承载新建／打开／导入等操作，目录继续显示当前项目的书籍页面、独立运行和成果。打开成片名称仍直接进入其所属项目，保留实验记录的限制。

复用当前项目和会话状态，不为此新增全局项目数据库、复杂最近项目系统或自动扫描未完成项目的机制。

## 8. 实施位置与顺序

| 批次 | 主要位置 | 内容 |
|---|---|---|
| 第一批：先理清流程 | `CreativeTimeline.tsx`、`CanvasWorkspace.tsx`、`CreativeComposer.tsx`，必要时少量展示辅助函数 | 任务归属、当前上下文、主操作与对话权限文案 |
| 第二批：降低阅读负担 | `CreativeTimeline.tsx`、`workbench.css` | 短摘要、审查依据、角色与轮次、展开状态 |
| 第三批：统一细节 | `WorkspaceHome.tsx`、`ProjectSidebar.tsx`、`CanvasWorkspace.tsx`、`workbench.css`，必要时 `App.tsx` | 成片库命名、直接继续、可读性、菜单与键盘行为 |

文件名表示预计改动边界，不要求拆新模块。复用现有任务、事件、来源与会话字段；先核对已有机制，只在确有缺口时做最小调整。

## 9. 最小验收

使用已有历史项目和本地模拟，重点核对以下场景：

1. 当前第 12 页待处理、其他页已有脚本时，每张任务卡均能识别真实归属；未知来源不误标成当前页。
2. 顶部连续制作、节点单阶段操作、输入框权限含义清楚；模拟的停止与续跑仍有效。
3. Creator／Reviewer 的退回、修订、通过有真实依据，摘要与展开内容分工明确；问题和恢复入口不被折叠隐藏。
4. 切换页、节点和创作／详情时，草稿、引用和阅读位置保持正确，不因新事件强制跳走。
5. Escape、键盘焦点、缩放中文标签和文字可读性在客户端实测；窄窗口与放大状态不遮挡主要操作。
6. 成片库只显示有视频的记录；继续当前项目直接回画布；打开成片仍进入正确项目和运行。

完成必要的类型检查、已有检查与构建。仅在新增的归属映射等逻辑确有独立价值时补少量检查，不为文案和样式铺设大量测试。

本轮界面验收默认不调用付费模型；涉及真实制作能力的结论必须另有真实验证证据。最后再用 Impeccable 复评，优先核对本方案的问题是否解决，不以提高评分本身作为交付目标。
