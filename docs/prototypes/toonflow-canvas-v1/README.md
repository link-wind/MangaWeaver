# MangaWeaver 画布视觉稿 v1

状态：**独立视觉提案，等待用户审阅；尚未实施到正式客户端。**

查看 `index.html`。目标窗口为 1480 × 980。所有素材均来自本地既有运行，不调用模型。

## 设计目标

采用 Toonflow 浅色画布的克制层级，让彩色关键帧与视频成为主视觉。保留 MangaWeaver 的漫画来源、镜头编排和 Creator／Reviewer 协作关系，避免把整个页面做成运行报告。

- 左栏 172px，作为安静的项目目录，只展开当前漫画页。
- 中央为浅灰点阵画布。节点标题放在媒体外，使用浅灰连线，只有当前视频片段使用轻微选中边框。
- 已完成的漫画分格收成一组；展开入口保留，避免六张高瘦漫画格常驻占满画布。
- 镜头编排保留简短的四镜头表；动作镜头明确显示入点和出点。关键帧保留原始画面与比例。
- 右栏 382px，以连续正文为主。对话中用一组紧凑行展示角色链；详细交接、产物入口集中在“协作”标签。
- 输入区只有一个容器，节点引用、文本、模型与发送操作放在同一容器里。
- 颜色：白色主表面、`#f9f9fb` 画布、`#26272c` 正文、`#e9eaed` 分隔线，低饱和紫色只用于选择与少量操作。系统中文字体，正文 12–13px，元信息 9–11px；本稿是桌面高密度编辑器，不使用展示型大标题。
- 普通媒体节点用单层边框，浮动工具轻描边，预览弹窗使用独立阴影；无渐变、无分隔线阴影。

## 素材与状态真实性

素材来自 `results/iruma-dialogue-page094-ja-20s-6panels/` 与其对应的本地漫画素材，清单见 `assets.json`。

第 94 页共 6 格，镜头编排时长为 4 + 8 + 4 + 4 = 20 秒。5 张关键画面来自同一运行；视频节点可打开真实镜头 03。实际视频审查中，镜头 01、02、04 通过，镜头 03 因约 0.7 秒意外硬切而退回。这一稿因此没有把全部产物标成完成，也没有声称成片已通过审查。

右侧消息为依据已有素材、镜头表与真实审查结果整理的**交互演示文案**，不是原会话逐字回放。前序阶段以已存在的选定产物展示“完成”，不据此伪造每轮审查日志。用户指令和待发送修订文案为示例。

## 可预览的交互

- “对话／协作”切换。
- 折叠 Agent 过程、展开漫画分格组。
- 从目录或反馈定位节点。
- 引用移除、节点引用恢复。
- 播放本地镜头 03 视频。
- 侧栏收起、缩放演示。

运行、发送、设置及其他未实现的入口会明确显示“视觉原型”或相应说明；没有接入引擎、模型 API、项目存储或正式客户端。

## 交付与检查

- `canvas-dialogue.png`：默认对话视图。
- `canvas-collaboration.png`：同一页面的协作视图。
- 两张图按 1480 × 980 的窗口、2 倍像素导出，为 2960 × 1960 PNG。
- 浏览器检查覆盖图片加载、对话与协作切换、节点选择、分格展开及顺序、视频预览开关与目录收起，结果见 `validation.json`。
- 本地视频可读取，实际时长约 4.46 秒；镜头表的 4 秒为规划时长。页面控制台无本轮错误。
- 画布分组预览采用紧凑缩略图；正式版展开后的节点排列、拖拽和连线行为仍应沿用客户端机制，这个原型不替代正式功能验收。
