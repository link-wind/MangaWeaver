# Toonflow 工程实现借鉴分析

日期：2026-11-02。状态：只读代码分析与增量建议，未实施。

参考本地 `Toonflow-app-master` 快照，未取得 Git 提交号；许可证为 MIT，Copyright 2026 HBAI-Ltd。此前 UI 观察和源码范围见 [界面参考记录](TOONFLOW_UI_REFERENCE_2026-11-02.md)。本报告不代表已验证其运行时行为或没有缺陷。

## 1. 结论与优先级

最值得学习的是：**关键操作有明确所有者、保存有版本依据、异步写回有归属校验、完成以回执为准。** 不需要复制其 Vue、Bun、插件脚手架或服务端架构。

| 优先级 | 借鉴点 | MangaWeaver 的处理建议 |
|---|---|---|
| 优先 | 保存前核对磁盘版本；切换前等待保存完成 | 围绕实际可编辑文件补冲突检测与保存完成边界 |
| 优先 | 唯一临时文件＋原子替换 | 继续用 `io.py`，避免固定 `.tmp` 名被并发覆盖 |
| 次优先 | 异步结果同时核对项目、运行、对象与请求 | 核查已有入口，补缺口；不新建状态框架 |
| 次优先 | 媒体 URL 有明确释放生命周期 | 保留本地流式协议，补 token 生命周期管理 |
| 按规模 | 流式事件归并与长列表虚拟化 | 先减少整段历史复制，确有卡顿再做虚拟化 |
| 继续复用 | 完成回执、任务身份、停止与恢复、事件去重 | 我们已有核心机制，不另建一套 |

## 2. 原子保存与并发边界

### Toonflow 的实现

`packages/file/src/index.ts` 的 `writeAtomic`：同目录下创建 UUID 临时文件，以独占方式写入，再替换目标；临时文件清理失败不会掩盖主错误。`packages/file/src/access.ts` 按规范化路径协调进程内读写，多路径先排序。

### 与当前项目对比

`src/mangaweaver/io.py::write_json` 已经是临时文件＋替换，并不是直接覆盖。但它使用固定的 `<目标>.tmp` 名；`run_lock.py` 的操作系统锁覆盖受保护的运行，不能由此推断所有项目级与只读进程都会受同一把锁保护。

### 最小建议

先确认会写同一文件的调用路径。需要增量时只在 `write_json` 内采用唯一临时名、可靠关闭与必要清理，保留统一原子替换。原子替换只避免半文件，不能解决“后写者覆盖先写者”的业务冲突。

不复制对方读写信号量、通用重试库和完整文件包；我们优先沿用运行锁，在确有项目级共享写入时才补对应边界。

## 3. 编辑保存的乐观冲突检测

### Toonflow 的实现

`apps/web/src/lib/workspaceFiles.ts` 提供 `readTextSnapshot`／`writeTextSnapshot`；后端 `apps/server/src/routes/workspaces/files/write.ts` 在持有文件操作锁时比较内容 SHA-256。磁盘版本不同则返回冲突，不覆盖文件；错误说明保留当前修改，允许重新读取或另存。

### 与当前项目对比

我们已有来源签名、引用签名和候选输入指纹，它们主要保证生成与引用一致性。它们不能自动等同于“用户读取文件到保存期间，其他入口是否改过这个文件”的编辑冲突检查。

### 最小建议

只给可编辑的来源、脚本或画布保存入口增加读取版本依据。保存时比较同一个文件／对象的签名，不匹配则保留草稿并报冲突。检查与写入需要处于同一受保护范围，否则仍可能在两者之间被修改。

不增加全文版本库、自动合并、依赖传播或所有产物的通用历史系统。

## 4. 切换前明确完成保存

### Toonflow 的实现

`pages/workspace/panels/canvas/canvasHost.vue` 暴露 `flushSave`；打开项目等控制流程在切换前等待保存。`panels/document/documentSession.ts` 将防抖保存和明确执行保存分开。

### 与当前项目对比

`CanvasWorkspace.tsx` 已有 600ms 草稿保存与按运行保存的草稿缓存，但防抖触发不是保存完成的保证；用户在此期间切换项目或退出的行为需要单独检查。不能把内存缓存当作磁盘持久化。

### 最小建议

保留防抖，在打开其他项目、离开有修改的编辑区及关闭应用的实际入口等待当前保存。保存失败保留草稿并阻止把失败表现成成功，不静默丢弃；不增加常驻重复确认弹窗。

## 5. 画布操作的真实完成回执

### Toonflow 的实现

`apps/server/src/agent/bridge/canvas.ts` 为调用分配身份，顺序发送变更；计时从实际执行开始，等待前端结果后才完成。回传验证工作区归属，取消与销毁释放等待，迟到回传幂等忽略。

`apps/web/src/lib/mcpControl.ts` 在切换工作区时取消旧调用，并区分命令身份与连接身份。

### 与当前项目对比

我们已有 `validateCanvasCommand`、call_id 去重、运行匹配、实际布局核对和 `onCanvasResult` 回执。定位、打开详情、布局移动不是“发送即成功”，这一点无需重写。

### 最小建议

后续增加命令时沿用既有合同，核对当前项目、运行与对象；多个变更如需顺序执行，使用一个小型队列。只在退出或切换时补齐未决命令的结束，避免旧回执影响新视图。

保留有限操作清单，不借此迁入 MCP 服务或任意前端执行接口。

## 6. 媒体加载、缓存与释放

### Toonflow 的实现

`apps/web/src/lib/workspaceFiles.ts::acquireUrl` 按工作目录、路径、媒体类型复用读取 Promise；使用计数归零时撤销 Blob URL，读取失败则移除缓存。替换或重命名资源会失效相关缓存。

### 与当前项目对比

我们通过 `desktop/electron/media.ts` 的授权 token 和 Range 响应流式读取本地视频，不是整文件 Blob 下载。`Media.tsx` 已防止组件卸载后更新状态；但每次 `media.url` 创建新的 token，`MediaFiles.tokens` 当前没有对应的释放入口，长时间浏览可能积累映射。

### 最小建议

保留授权与流式传输；考虑由组件租用／释放 token，或在可明确界定的项目关闭边界清理已无使用者的 token。仍在播放的实例不能被其他节点卸载误清理。若增加缓存，资源替换必须同步失效。

不能将这个内存生命周期问题直接认定为此前视频无法播放的根因，也不应复制 Blob 全量读取大型视频。

## 7. 流式消息：学习合并方式，避免重复建设

### Toonflow 的实现

`components/agent/replyStream.ts` 解析换行 JSON 事件，以 blockId 定位消息片段；约50ms合并文字，结束时补齐。只有明确 done 才视为完成，意外 EOF 报中断。工具与公开正文在同一消息内按片段组合。

### 与当前项目对比

我们已经有50ms批处理、按事件身份／sequence 去重、分支过滤和中断处理。这些不是待新增能力。当前 `conversationEvent` 每次都 `structuredClone` 整段 conversation，同一批增量通过 reduce 多次归并，因此历史较长时可能产生不必要的复制。

### 最小建议

先观察真实长会话开销；必要时每批只复制一次，再更新受影响 turn／block。保留去重、事件顺序和分支隔离，不用假的打字效果替代真实流式。

这段 Toonflow 前端代码读取的是换行 JSON，不应笼统把它称作 SSE；模型上游的 SSE 与应用事件传输是不同边界。

## 8. 长对话的阅读性能

### Toonflow 的实现

`components/agent/conversation/messageList.vue` 使用虚拟列表，按实际消息高度测量，流式追加更新当前项；用户离开底部后显示“回到最新消息”。正文、工具和附件分别渲染。

### 与当前项目对比

我们已按距底部70px决定自动跟随，但仍一次渲染完整历史。阶段活动、技术 JSON 与媒体多时，可能增加 DOM 和滚动更新成本。

### 最小建议

先减少未展开详情的工作量与事件复制。只有实际长历史出现卡顿，再在现有历史区域增加可变高度虚拟化，并核对任务定位、展开状态、流式高度、搜索和焦点行为。不要因为对方使用库就立即引入依赖。

## 9. 异步生成结果的归属与落盘

### Toonflow 的实现

`packages/nodeShared/src/useNodeGeneration.ts` 在应用状态或结果前检查当前节点实例、工作目录、画布与 taskId，任务输出的 applied 状态只有保存成功才成立；失败时还原该标记。恢复已有任务优先于创建新请求，未知提交结果明确提示核查。

### 与当前项目对比

我们已有任务 ID、输入指纹、候选状态和显式恢复流程，不能替换成前端自行生成一套任务。值得逐入口检查的是：用户切换页面／项目后返回的旧结果、写入失败时是否错误显示完成、候选采用与实际保存顺序。

### 最小建议

沿用已有 run／task／signature，写回前核对一次当前所有者，保存成功后再发布完成。不要仅凭组件当前选中状态决定后台任务归属。

## 10. 停止与取消必须有明确范围

### Toonflow 的实现

`apps/server/src/agent/runtime/sessions.ts` 在授权与初始化期间就登记 active run；停止按工作区与运行身份匹配，并等待 finished。`runtime/delegation.ts` 组合父级与子级取消信号，finally 释放桥接和等待。

`useNodeGeneration.ts` 明确说明停止等待不能保证供应商撤销任务或费用。

### 与当前项目对比

我们的 Electron 引擎在启动后登记进程，并支持进程组 SIGINT／SIGTERM／SIGKILL；已有停止后检查点恢复，不需搬入 AbortController 服务架构。

### 最小建议

复核初始化、问题等待、子任务和画布等待是否都能进入结束状态。保持“停止本地执行”“停止等待远端”“供应商确认取消”三者区分，界面只说已有证据支持的结果。

## 11. 分页与固定引用

Toonflow 的 `agent/mentionSources.ts` 将引用搜索游标绑定 revision、query 与 offset，来源变化后拒绝继续使用旧游标；`agent/mentionFiles.ts` 以文件状态缓存读取。

我们的固定引用已经有内容签名与项目归属校验。若整本漫画引用列表变大，可以借鉴“元数据分页＋按需读取”：搜索先返回页码／节点名／缩略图，真正引用时再固定签名。缓存不替代签名校验，也不默认把整本所有原图发送模型。

## 12. 不直接借鉴的部分

- 不迁入 Vue／Bun／Express 服务端，也不把确定性文件操作包装成新 Agent。
- 不照搬插件注册体系、通用读写调度包、完整虚拟桌面或自动回退。
- 不复制其内部思考内容展示；我们继续处理公开说明、结构化审查和真实工具事件。
- 不因为参考源码包含远端取消、模型目录或账户接口，就推断我们所用视频渠道支持这些能力。

本轮只新增分析文档。后续进入 OpenSpec 时，建议先选“编辑保存冲突与切换前保存”，再选“媒体生命周期与异步归属”，最后根据实际卡顿决定流式和列表性能优化。
