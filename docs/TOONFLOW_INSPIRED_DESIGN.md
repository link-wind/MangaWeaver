# MangaWeaver 工作台设计方案：借鉴 Toonflow

日期：2026-11-02
状态：待确认的设计提案，不代表功能已实现。
适用范围：首页、漫画素材库、成片库、画布、节点编辑、创作对话、协作详情、设置与反馈。

## 1. 设计目标与依据

将 MangaWeaver 整理成一个以漫画和动画产物为中心、能够中途修改、能看懂多 Agent 协作过程的桌面创作工具。

借鉴 Toonflow 的内容组织、对象就近操作、输入工具行与渐进展开方式，继续采用 MangaWeaver 已确定的白色简约风格、轻字重、小导航和三栏画布。设计重点是让用户知道：正在编辑什么、发生了什么、接下来会执行什么。

依据分为三类：

- **用户截图**：本轮提供的设置与素材库截图，明确呈现分类导航、内容分区、卡片、搜索、主要操作和弹窗布局。
- **实际应用观察**：首页、已有项目画布、选中图片节点、文档面板及历史对话。模型设置等页面的实机切换曾异常，不能将其全部视为验证通过。
- **本地源码核对**：页面路由、节点编辑、候选历史、消息与工具记录、排队／引导、子 Agent 入口和设置分类。详细文件位置、快照指纹与观察边界见 [参考记录](TOONFLOW_UI_REFERENCE_2026-11-02.md)。

截图补足了之前设置与素材库的视觉信息；截图中的账号信息和完整原图不纳入项目资源。截图可证明布局，不证明余额接口、上传、计费或运行行为。

## 2. 参考取舍

| 参考内容 | MangaWeaver 的采用方式 | 优先级 |
|---|---|---|
| 素材库的分类、搜索与操作区 | 形成漫画书架及选材面板，保留封面与页数 | 第一批 |
| 节点选中后展开工具和参数 | 默认只展示产物，选中后编辑；长文本可进入详情 | 第一批 |
| 工具过程折叠、正文连续阅读 | 保留阶段任务，压缩确定性工具记录 | 第一批 |
| 对话中的节点定位与引用 | 显示页码、镜头名与缩略图，双向定位 | 第一批 |
| 设置的左分类、右内容结构 | 先整理已有本机环境设置，类别按实际能力出现 | 第一批 |
| 当前任务引导与下一轮排队 | 统一送达文案与队列状态，复用既有运行时 | 第二批 |
| 子 Agent 查看入口 | 阶段内查看 Creator／Reviewer 的真实记录 | 第二批 |
| 媒体历史与当前输出 | 先浏览，再显式采用经审查的版本 | 第二批 |
| 模型管理、用量与任务记录 | 独立配置提案；只显示可核实信息 | 后续按需 |

“参考”不意味着增加 Toonflow 的全部模块。所有候选尺寸、菜单与文案都需结合现有组件校准，不引入第二套 Agent 系统、数据库或服务。

## 3. 全局布局与视觉语言

### 3.1 导航层级

全局导航为“开始创作／素材库／成片库”，设置固定底部。首页保留轻量项目入口；进入画布后左栏展示当前漫画、页码、运行和成果。成片库继续只显示有最终视频或预览视频的记录。

项目身份只在一个主要位置展示；画布制作工具区显示本次范围和终点，对话输入区显示本次操作对象。不同位置的信息含义不同，避免重复堆叠同一项目名或“当前页”。

### 3.2 视觉基准

- 白色内容区、浅灰侧栏与画布；黑色主按钮，少量紫色标识选择和焦点。
- 主文字 `#24242B`、辅助文字 `#666671`；不得用继续降低对比度的方式减少视觉重量。
- 主标题 30–32px／400，页面标题 20–22px／500，正文与输入 14px／400，辅助元数据 12px。
- 系统中文字体与 Lucide 图标；主要通过留白、对齐、字重形成层级，不照搬截图的深色、蓝色或字体。

## 当前源码组件核对（2026-11-04）

本轮直接读取用户本机的 `/Users/linkwind/Downloads/Toonflow-app-master/apps/web/package.json` 与相关组件入口，不把历史截图或记忆中的依赖当成当前事实。Toonflow 当前前端是 Vue 3，界面由多套职责明确的构件组成：

| 界面职责 | 当前构件 |
| --- | --- |
| 通用按钮、表单、弹窗与菜单 | Element Plus |
| 对话容器、消息和 Agent 展示 | TDesign Vue Next、TDesign Chat |
| 对话输入 | x-sender |
| 节点画布 | Vue Flow、Background、Minimap |
| 工作区标签与面板 | Dockview Vue |
| 图标 | Tabler Icons Vue |
| 富文本 | Tiptap |

Toonflow 的 `apps/web/src/assets/main.scss` 把 TDesign 的品牌色变量映射到 Element Plus，并用统一的 `--ui-radius` 控制圆角。这种“指定主组件，再把附属组件的语义 token 接到同一主题”的做法值得借鉴。

MangaWeaver 不追随 Toonflow 同时使用多套通用组件库。当前应用是 React，基础交互继续使用 shadcn/ui Radix 源码；React Flow 负责画布，Lucide 负责图标。减少组件体系后，字体、字号、控件高度和语义颜色只需维护在 `desktop/src/theme.css`。此前视觉不一致来自旧页面 CSS 继续覆盖新组件，应由收敛主题和删除失效规则解决，不需要再安装 Element Plus 或 TDesign。
- 控件圆角约 8px，卡片约 12px；只在浮层需要区分覆盖关系时使用轻阴影。分栏始终使用贴合边缘、无阴影的细线。
- 三栏可调整、可收起且始终有展开入口；保留用户已有宽度。新用户初始值参考左栏 192px、右栏 360px，其余留给画布。

### 3.3 弹层共用规则

设置、选材、候选历史使用一致的标题、关闭位置、边距和内容滚动区。桌面大窗口可采用约 960–1080px 的宽弹层，受窗口可用空间约束，不将截图比例硬编码。

弹层内部有清晰的分类或选择状态，标题及必要确认按钮不随长内容消失；小窗口改为可滚动的单列／抽屉，避免双重横向滚动。Escape 与关闭按钮行为一致，关闭后焦点返回触发入口；设置弹层关闭不丢画布位置和输入草稿。

## 4. 首页：输入、素材与保存位置

首页只承担开始创作和继续已有工作。

- prompt 是视觉中心，漫画附件以小缩略图、名称和已知页数展示，支持移除。
- 底部工具行放“添加漫画／从素材库选择／更多”，右侧发送；高级选项收进菜单。
- 保存到的项目以轻量字段展示，点击查看或选择。沿用既有新建／打开流程，不因一次发送重复询问目录。
- 用户提交后立即进入画布并显示正在导入／预处理状态。整本先加载 10 页，页数未知时显示“读取中”，不伪造进度。
- 同一份素材通过本地文件与书架选择时，后续进入相同的选页流程。

下方最近成片以封面和名称为主，轻量播放按钮开始播放后才显示完整控制。名称点击继续原项目，另有明确“查看制作过程”操作定位该成片的运行；缺失原项目时清楚说明，不进入错误的当前项目。

## 5. 素材库：管理与选材分开

### 5.1 从截图学习的结构

截图将目录导航与内容分开，内容顶部集中放标题、数量、搜索、新建目录和导入，卡片只保留预览与简短信息。这种组织比把所有操作散放在卡片上更清楚。

MangaWeaver 采用“左侧应用导航＋漫画书架”。现阶段无需在应用导航旁再增加一个空目录栏；有真实分组需求后，再考虑文件夹。第一版可用“全部／整本漫画／单页”筛选，不机械复制图片／视频／音频类别。

### 5.2 漫画卡片

| 默认显示 | 按需显示 |
|---|---|
| 封面、名称、页数、格式 | 完整文件名、导入时间、来源位置 |
| 整本或单页类型 | 查看页面、添加到创作、更多操作 |
| 可理解的读取状态 | 读取失败详情与重新导入入口 |

MOBI／PDF 等已提取封面时优先展示封面，不能长期仅用通用文件图标。封面使用统一展示区并完整容纳；长书名最多两行，完整名称可查看。

只收录主动导入的素材；打开项目或查看成片不自动加入书架。重复导入沿用现有去重。删除和移动等尚无实现的操作不先放成无效按钮。

### 5.3 选材面板

从首页或对话打开选材时，使用同一素材数据的选择模式，支持搜索和预览。选中后明确“添加到创作”，关闭即返回原输入，保留 prompt、引用与滚动位置。可以在面板内显式导入新漫画，完成后仍留在当前选材流程。

选择整本后不自动生成；进入画布后选择需要改编的页，保持逐页加载和已有运行映射。

## 6. 画布：对象优先、操作就近

保留“整页漫画 → 有序单格 → 镜头规划 → 关键画面 → 视频”的真实产物主线。漫画格与镜头之间的多对多来源映射不因自由画布而丢失。

### 6.1 节点三种状态

| 状态 | 内容与操作 |
|---|---|
| 未选中 | 标题／来源页、媒体或短摘要、真实阶段状态 |
| 选中 | 明确选择边界；显示该对象的查看来源、审查、修改／单阶段执行入口 |
| 编辑 | 提示词／内容、参考素材和必要参数；明确保存与执行的区别 |

借鉴 Toonflow 的上下工具区域，但不要把完整编辑器随画布缩放到不可读。较长脚本、翻译和审查记录继续放详情区或独立编辑面板；节点旁只提供常用操作。

编辑保留草稿；切换节点时标明当前对象。保存草稿不触发模型，开始修订才调用现有阶段。已提交视频的上游修改沿用既有新修订运行，不能改掉旧产物的来源关系。

### 6.2 画布导航

提供“定位当前页／定位选中／适应画布”，含义分别明确。搜索节点支持页码、阶段、镜头名，结果可直接定位。全书总览与当前工作视图分开，不因出现新产物就把全部节点缩成小字。

同列分组折叠后展示封面、数量和状态，展开恢复位置与顺序。整理布局是显式操作，已有手动布局不会被生成事件自动覆盖。

节点进度区分未知比例、已完成、失败与等待审查。生成完成不等于审查通过；已有视频也不等于质量合格。

## 7. 参考素材与视频节点

参考卡片显示缩略图、名称和用途：**首帧／尾帧／角色参考／普通参考**。只有确实支持的后端输入才允许相应角色；整张故事板参考不能标成首尾帧控制。

首尾帧顺序通过显式标签表达，拖动或替换时同步更新引用，不让连线先后成为唯一依据。提交前集中显示模型、分辨率、时长和本次生成对象；参数不被节点与设置页重复覆盖。

视频节点提供播放、声音、时间、全屏及下载。历史记录以缩略图列表＋预览呈现，标注当前采用项、审查状态和来源版本。

**浏览历史不改变输出。** “采用此版本”是独立操作：仅能采用来源匹配且满足原审查流程的候选。被拒绝候选可查看原因，不能通过界面直接绕过 Reviewer。没有合法候选时明确报错，不默认选择第一个。

## 8. 创作对话与多 Agent 协作

### 8.1 消息层级

对话正文连续阅读，不给每段回复套大卡片。用户消息、Agent 正文、阶段任务和工具过程使用不同层级：

- 正文说明决策与结果。
- 阶段任务显示来源、阶段、真实角色、状态和短结论。
- 工具默认显示一行“名称＋状态”，参数／结果展开读取。
- 原始网络错误与长路径折叠，默认说明失败点和可用操作。

避免在每张任务卡前重复“创作 Agent”，避免摘要、公开说明和审查依据重复全文。公开文本按已有真实流式事件追加，不制造打字效果，不新增暴露内部推理的要求。

### 8.2 Creator／Reviewer 的呈现

每个制作阶段可展开“查看协作”：按轮次显示 Creator 的产物、Reviewer 的通过／退回、问题及修订结果，并能定位对应节点。必要时可从顶部查看当前阶段参与角色，但不能把确定性工具计为 Agent，也不能虚构角色互聊。

协作详情仍隶属原阶段任务，返回后继续原会话，不要求复制 Toonflow 的独立子会话框架。优先把已有 activities、问题和版本数据展示清楚。

### 8.3 运行中修改与排队

复用现有送达机制，输入区清楚区分：

| 用户意图 | 展示与反馈 |
|---|---|
| 修改当前制作 | “引导当前任务”，显示是否已接收、何时可处理 |
| 等本轮结束再做 | “加入队列”，显示待处理条目和对象 |
| 停止本地执行 | 显示停止中与最终停止状态；保留可恢复产物 |

排队条允许现有能力支持的撤回、编辑和开始处理。不能声称补充要求会撤销已完成操作，也不能把本地停止表达成远端收费任务必然取消。快捷键沿用 MangaWeaver 当前习惯，不直接复制对方 Enter 行为。

### 8.4 引用与阅读位置

节点引用显示页码、名称、用途和必要缩略图，点击可以定位；不以 UUID 作为默认文字。支持从节点加入对话，也支持从消息返回节点。

用户翻看历史时不强制滚到底部，提供“回到最新”入口；新文字不改变正在阅读的展开状态。历史对话和分支集中在菜单管理，不占据常驻流程空间。

## 9. 设置：借鉴布局，按需增加功能

用户截图中的左侧分类、右侧标题／信息卡／子标签和独立滚动区可用于设置。MangaWeaver 不需要复制账号卡、钱包和商业后台。

### 第一批：已有本机设置

先提供“本机环境”和“关于”两类实际内容：项目根目录、Python、FFmpeg、环境文件路径、依赖检测、应用版本与查看本地日志。路径允许复制与定位，检测状态与错误就近展示。

类别少时不使用复杂分组，类别增加后再分组。无内容的分类不先占位。路径选择取消不改变现有配置；切换设置分类和关闭面板保留画布与草稿。

### 后续提案：模型与用量

若用户确认扩展，可将文本／评审、生图、视频按职责分类。模型列表以已配置渠道为基础，明确可用、未验证和不支持的能力；显式保存，不自动换模型或回退。

凭据隐藏显示，编辑不回传到日志或截图。连接检查说明是否会调用收费接口；查看设置不做付费探测。

用量只展示已记录请求数、模型返回用量、平台实际费用或明确标注的估算。未知余额显示“未提供”，未知费用不补成0；不在无数据时制作钱包、金额卡片和消费图表。

网络、设备互联、本地记忆和插件市场单独作为未来需求讨论。本方案不授权开启服务、扩大访问范围或建设充值系统。

## 10. 反馈、键盘与窗口行为

- 错误出现在相关输入、节点或任务旁，保留完整原因供展开。可恢复、待回答、审查退回分别表达。
- 关键状态同时使用文字与图标，不仅靠颜色；图标按钮有名称和键盘焦点。
- 所有悬停操作同时支持聚焦或菜单访问。弹层阻止操作背后页面，关闭后恢复焦点。
- 三栏拖动使用透明命中区和边界细线；窄窗口不挤出负宽度。布局限制与应用最小窗口尺寸协同。
- 微交互只表达选择、展开、送达和完成；支持减少动态效果，运行中不因重排让按钮跳位。

## 11. 实施顺序与边界

| 批次 | 交付 | 依托现有实现 |
|---|---|---|
| 1 | 首页工具行、素材管理／选材、节点操作层级、设置外壳 | WorkspaceHome、MaterialLibrary、CanvasWorkspace、EnvironmentSettings |
| 2 | 连续对话、折叠工具、协作详情、送达／队列、双向引用 | CreativeTimeline、CreativeComposer、现有会话与任务数据 |
| 3 | 节点搜索、候选历史、版本预览与采用入口 | 已有节点、候选、Reviewer 与来源签名 |
| 后续确认 | 模型／用量、分组目录等独立扩展 | 先确认接口和真实需求，再规划 |

本轮只交付设计文档。进入实施时建立或修订 OpenSpec，复查现有功能后仅补缺口；不把表中组件名当成必须重写的边界。

最小验收覆盖：从书架选一本漫画返回原输入、选页后定位正确画布、选中节点编辑并保留草稿、查看 Creator／Reviewer 退回与修订、运行中送达与队列、从消息定位产物、预览候选但不改变正式输出、关闭设置后恢复原状态。视觉在实际客户端常用窗口及最小窗口检查，接口行为只报告实测范围。
