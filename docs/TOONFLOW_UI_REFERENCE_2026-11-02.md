日期：2026-11-02。方式：读取用户已打开的 `/Applications/toonflow.app`，通过应用接口观察界面与操作。未修改 MangaWeaver 代码，未提交生成任务或上传本地素材。

## 观察与边界

- 首页有固定侧栏，首页／项目／探索与素材库分组，设置和设备入口位于底部；首页导航可定位同页不同内容区域。
- 创作输入承载附件、工作目录和模型／思考强度入口，未选目录时给出具体下一步及文件保存位置说明。
- 项目区将新建与打开已有目录作为一个明确入口。当前没有观察到已有本地项目。
- 探索区以大封面、作品名和作者展示内容；作品详情提供播放、说明和“查看制作过程”。点击制作过程返回网络错误，未验证云端画布或生成时任务过程。
- 素材库可访问性结构包含目录、搜索、新建文件夹、本地上传及图片／视频／音频等类型筛选。当前素材库为空，未验证真实素材的选择与复用。弹层截图未可靠显示，因此不能据此断言具体弹层的视觉尺寸。

## 对 MangaWeaver 的建议

1. **输入区统一工具行。** 漫画附件／素材库、项目位置与发送构成固定底部工具行。必要时明确显示当前保存项目，避免用户发送后才发现操作归属。模型等低频配置继续按需展开。
2. **管理与选材使用不同容器。** 左栏素材库保留完整书架管理页；从输入框选材时使用可返回原输入的选择面板，不丢草稿。第一版仍只管理漫画，不扩展音频、云端资源或复杂文件夹。
3. **成片到过程的连接。** 成片展示突出封面和播放，提供明确的“继续编辑／查看制作过程”入口，落到已有项目与对应节点。沿用只列有成片记录的既定约定，不另建项目数据库。
4. **留白和控件层级统一。** 保留白色主题，将输入、内容卡片、工具行作为三个层级，避免重复说明、常驻技术细节及同级按钮过多。学习组织与状态反馈，不照搬深色主题、装饰背景或产品标识。
5. **缺少前置条件时直接指向下一步。** 没有漫画时引导添加漫画；没有项目时说明保存位置；任务被审查阻断时显示具体问题和对应操作。不能用通用错误或一直转圈代替。

### 最值得借鉴的交互

1. **节点平时只展示产物，选中才显示编辑。** 图片节点上方出现工具栏、下方出现提示词与参数。MangaWeaver 可以将来源／审查／修订入口就近放在选中对象旁；详细长文本继续使用详情区，避免缩小时把编辑器也缩成小字。
2. **正文、工具过程与结果引用分开。** 工具默认折叠为名称＋状态，参数和结果展开读取；正文保留连续阅读。我们将创作／审查业务阶段作为任务主线，文件操作放到次级工具记录，不需要同等大小的卡片。
3. **对话直接定位相关节点。** 历史记录中有多个“聚焦节点”按钮。我们应保留具体页码和节点标题，以同一引用完成对话与画布双向定位；不能退化为 UUID 展示。
4. **运行中输入有明确送达模式。** 代码区分 steer（引导当前任务）与 followUp（本轮完成后处理），队列可编辑、删除或转引导。我们已有相关机制，先明确输入框和排队条的反馈，不再增加一套运行状态系统。快捷键沿用 MangaWeaver 当前习惯，不直接照搬对方的 Enter 行为。
5. **子 Agent 有独立查看入口。** `agent/menu.vue` 显示子 Agent 名称、状态、摘要，可进入并返回父 Agent。我们可为 Creator／Reviewer 提供阶段内“查看协作”入口，展示真实轮次和审查依据；不要求把每个阶段都变成独立聊天或增加 Agent。
6. **对话面板可以停靠或悬浮。** 已有 UI 入口和源码支持。我们先保留可调整的三栏，增加显式收起／展开即可；悬浮不是本轮必须项，避免遮挡节点或引入额外拖动状态。
7. **画布工具成组且有明确用途。** 布局整理、地图、连线、适应视图、缩放与节点搜索分区放置。我们优先补强搜索节点、定位当前页和选中范围，避免始终适应整本漫画而不可读。
8. **媒体版本按需查看。** 节点有历史记录、替换、下载、全屏等入口。我们可以直接呈现已有候选与选中版本，不复制通用媒体编辑器或允许版本选择绕过 Reviewer。
9. **文档与画布共享工作区。** Toonflow 支持文件树、文档标签和画布节点互通。MangaWeaver 当前只需要把脚本、对白、审查依据编辑整理好，暂不搬入完整 IDE 或 Dockview。
10. **设置采用分类与独立内容区。** 我们当前用户只授权本机环境设置，先优化现有布局；模型配置、插件市场、账号、云端探索等不因参考而加入实现范围。

### 新增的重点结论

- **操作前说明对象与影响范围。** 参考图用途、当前输出版本、未来调用权限、运行中引导都需要明确含义，比增加更多按钮更重要。
- **历史选择与结果采用分离。** 浏览不应修改选中产物；应用新候选需沿用现有审查、版本和恢复规则。
- **媒体操作就近，系统配置集中。** 节点侧只放当前镜头／画面的操作；渠道、目录和环境在设置中管理，避免节点与全局设置相互重复。
- **需避免同样的复杂度。** 我们不复制多租户、账号充值、插件市场、通用文档IDE等大模块，也不直接搬入对方 Vue／Bun 的框架层。
