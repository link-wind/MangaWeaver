# 整本漫画工作区设计方案

日期：2026-11-06
状态：用户确认实施，OpenSpec `add-book-workspace`；双页对照已取消。

## 1. 目标与判断

让用户在同一个项目中管理整本漫画、选择制作范围、查看各页进度，同时保持当前创作内容可读。默认不再将多页的全部产物铺到一张超长画布。

推荐采用「全书总览＋单页工作画布」。保留现有三栏、白色轻量视觉、媒体外置标题和创作助手，不增加第四个常驻面板。

本方案假设：精细编辑通常围绕单页，批量任务需要观察多页状态，但不需要同时操纵所有页面的全部节点。跨页编排成一个连续场景不是本轮新增目标。

## 2. 当前问题

当前 `bookGraph()` 遍历已关联的页面运行，为每一页追加整页、分格、规划、镜头、关键画面和视频节点，再将下一页放到更下方。即使缩略图每次只加载10页，已经展开的产物图仍然持续累积；按需加载与画布信息过载是两个问题。

已有页面折叠可以减少节点，但用户仍要在大图中找到页卡、展开并重新定位。全书缩放后内容难读，恢复工作位置也不直接。

当前 `BookPicker` 放在可缩放的书籍节点内，混合了浏览缩略图、多选、展开范围和跳页。用于导航的界面也会随画布缩放与平移，定位成本偏高。左栏已有上一页、下一页和页码跳转，可继续复用。

此外，左栏选页和选页器目前受全局 busy 限制。浏览其他页与修改正在执行的产物应分别处理，避免任务运行时整个项目无法浏览。

## 3. 方案比较

| 方案 | 优点 | 问题 | 决定 |
| --- | --- | --- | --- |
| 保持全书大画布，只加强折叠 | 对现有结构改动小 | 页面多时仍需长距离寻找与缩放；导航问题保留 | 保留折叠能力，不作为主要方案 |
| 全书总览＋当前页画布 | 总览看进度，当前页精细编辑；边界清楚 | 需要保存每页工作位置和明确切换语义 | 推荐 |
| 每页独立标签，任意多个标签同时打开 | 页面之间切换快 | 上百页时标签管理变成第二套目录，界面更拥挤 | 首版不采用 |

首版不实施双页对照。

## 4. 全书总览

### 进入方式

- 整本漫画首次导入后进入全书总览。
- 左栏书名可返回总览。
- 当前页工具栏提供「全书」返回入口。
- 重开项目时恢复上次所在视图；首次使用才以总览为默认。
- 单页素材直接进入现有单页画布。

### 页面内容

中央区域采用稳定尺寸的页面缩略图网格，不随 React Flow 缩放，不展示全书全部业务连线。每张页卡常态只有原页缩略图、文件页码和一个简短状态。

状态来自实际产物与任务：未开始、制作中、需处理、已有成片。详细阶段与错误在选中页后按需查看，不在每张卡上堆进度条、阶段按钮和多行说明。

顶部只保留页码跳转和状态筛选。首屏延续最多10页缩略图的加载策略，随后分批载入；不为了显示总览读取每页全部规划和媒体。

### 选择与打开

- 单击页卡选择页面，显示选中状态；不会切换工作画布或启动制作。
- 双击页卡进入该页画布；同时提供明确的「打开页面」操作，支持键盘。
- 使用显式选择按钮或 Shift 范围选择多页。
- 有批量选择时才出现选择操作条，例如「已选3页 · 打开第94页 · 制作所选3页」。
- 浏览、选择和打开页面均不提交模型请求；只有明确点击制作或确认 Agent 的制作提案才运行。
- 页卡预览不创建制作任务或批量运行目录；进入工作画布时复用已有运行，尚无运行的页面显示原页待制作状态。

全书总览属于中央工作区，不放进一个大弹窗，也不把十张缩略图常驻到左栏。

## 5. 当前页工作画布

中央画布只投影当前页的真实产物，保留现有从整页到成片的流程、分组、连线、右键菜单和删除确认。

工具栏增加紧凑的页面上下文，例如「全书 / 第094页」，配合上一页、下一页和页码跳转；导航只保留一组，替代左栏当前重复的页码控制。左栏保留书名、进入全书总览及现有项目导航。

「全流程总览」只适应该页的全部节点；「返回当前镜头」仍定位当前页的镜头产物。不会因制作另一页而突然把整本漫画缩到一起。

每页分别记住缩放、平移、节点位置、折叠组和最近选择。切回第94页时，回到离开前的镜头位置，不重新适应全书。

首版不新增一排常驻页面标签，也不在每个节点重复印大页码；页面身份通过工作区导航统一表达。

## 6. 取消双页对照

2026-11-06 用户明确取消双页对照。本轮只保留全书总览与单页画布，不新增对照入口、双视口或跨页节点连线。原型中的对照页面仅留作历史视觉记录。

## 7. 批量制作与后台任务

必须分清三个对象：

| 对象 | 含义 | 影响 |
| --- | --- | --- |
| 正在查看的页面 | 当前中央工作区的页面 | 决定画布取景与「这页」的指代 |
| 选择的制作范围 | 用户在总览选中的页或明确输入的页码范围 | 仅在明确提交时成为批量任务的目标 |
| 正在执行的页面 | 已提交任务当前处理的页 | 显示进度，不自动改变正在查看的页面 |

例如：用户提交94～96页，当前执行95页，仍可回到94页看已有关键画面。任务切页不抢画布焦点。

运行时在原运行控件附近显示紧凑信息，例如「第95页 · 关键画面 · 2/3页」，可点击定位运行页。总览同步更新真实状态。沿用已有停止、恢复和任务账本，不引入新的并行调度框架。

首版只需放开只读浏览，正在执行目标的重跑、删除等操作继续遵守现有互斥与确认规则。不为这个功能扩大到并发编辑同一运行。

## 8. 创作助手与多 Agent 呈现

创作助手仍是项目级会话，不为每页新建一个聊天窗口。

- 页面相关消息带轻量页码引用，跨页任务的协作记录按页归属。
- 当前页视图默认聚焦该页及涉及该页的跨页任务；提供一个「当前页／全书」筛选，不再增加一排新的聊天标签。
- 全书总览展示项目级对话及批量任务。不同运行的审查结果分别保留，不混成一个「全部通过」结论。
- 后台制作其他页时，保留一条紧凑的运行状态入口；用户主动打开后再展开相应 Creator／Reviewer 记录。
- 用户输入「将这页改成彩色动画」，提交时固定当前页身份；「处理94～96页」固定明确范围。仅在总览多选、尚未提交时，不默默将普通聊天变成批量制作。
- 页面切换不丢草稿、不清空手动引用、不改变已提交请求的目标。带引用的草稿仍指向原对象；没有手动引用的非空草稿保留起草时的页面引用，防止切页后误发。
- Agent 可以执行明确的选页和聚焦请求；后台专业任务的进度不自动发出页面切换命令。

多 Agent 特性通过「哪一页、哪一阶段、谁创作、谁审查、为什么退回」体现，不通过同时展示更多卡片或日志体现。

## 9. 工程落点

这是工作区视图和上下文管理的增量修改，不调整三阶段生产协议与模型接口。

- `ProjectSidebar.tsx`：书籍入口返回总览，精简重复的页码导航。
- `BookPicker.tsx`：范围解析、缩略图加载和选择逻辑复用，呈现从画布书籍节点迁到总览区域。
- `CanvasWorkspace.tsx`：根据总览、当前页投影视图；当前页默认只传入一页业务图。
- `bookCanvas.ts`：继续复用页面内业务节点和分组投影，不再默认展开所有已有关联运行。
- `CanvasView` 及已有持久化：按页记住视口和选择，保留旧节点位置；只补实际需要的字段。
- `CreativeTimeline.tsx`：基于已有任务的运行／页码身份过滤展示，保留原始项目会话。
- 沿用 React Flow、现有 shadcn/Radix 与 Resizable，不为此引入新的画布库、数据库或 Agent 服务。

旧项目关联关系、产物、消息和保存坐标不变。关闭页面和切换视图仅改变视图，永远不清理生成结果；删除继续由现有节点菜单和明确的二次确认负责。

## 10. 建议实施顺序与验收

本轮完成全书总览、单页隔离、每页视口恢复、稳定的请求目标及后台运行分离；不实施双页对照。

关键验收使用一本真实漫画和少量本地已有产物：

1. 总览可查看和选择100页以上的索引，首屏不加载所有图像及运行产物。
2. 打开第94页，画布只展示第94页业务节点；切到95页后再回来保留原取景。
3. 在总览提交94～96页，查看页与运行页独立；运行过程中浏览其他页面不启动新任务。
4. 第94页草稿和镜头引用在切页后仍绑定94页，不被改成95页。
5. 切页和返回总览不创建运行、不清理产物；批量制作只在明确提交后开始。
6. 审查退回归属确切页和镜头；用户可从对话进入相应页面与节点。
