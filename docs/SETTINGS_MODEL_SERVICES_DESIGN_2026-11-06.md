## 弹窗结构

建议常用窗口下约1120×760，最大尺寸受窗口留边约束。左侧约160px设置导航固定；右侧内容滚动。最小1080×720窗口缩至可用区域，不叠出多个同级滚动面板。

分类为：

1. 模型服务：厂商、接口、凭据和模型目录。
2. 任务模型：四类任务使用的服务与模型。
3. 生成偏好：已有时长、候选数量、审查轮次与输出参数。
4. 本机环境：现有路径和依赖检查。
5. 关于：版本与项目说明。

标题、关闭按钮、保存操作有稳定位置。退出有未保存内容时提醒；保存成功后不在页面常驻大提示条。

## 模型服务

内容采用供应商列表与详情的主从布局。列表只显示名称、支持的任务类型和是否已配置，不放重复说明或大图标卡片。

选择厂商后，右侧展示名称及文本／图像／视频分段控件；只展示该适配器实际支持的类型：

- 连接名称，用于区分同一厂商的不同入口。
- 接口地址；预设提供默认值，允许在对应适配器支持的范围内修改。
- API Key，默认遮挡；只显示已设置状态，不从主进程回传原密钥。
- 文本／图像／视频凭据分别配置。不能将幻灵三组独立Key合成一个通用Key。
- 模型条目显示名称和实际模型ID，可添加／编辑；模型存在于列表中不代表已验证或已启用。

初期以已有适配器为边界：幻灵、Google Gemini、Kie.ai、词元、MiniMax。添加连接先选择适配器，再填写地址和凭据。OpenAI兼容文本若后续决定增加，需要独立适配；本稿不将任意自定义视频厂商或模型当作已支持功能。

详情底部保留“检查格式”和“保存更改”。“检查格式”只做本地字段校验，不自动发起生成。每个模型条目提供“测试”或“真实测试”：文本发送最小文本请求，图像与视频发送一次真实请求并提示可能产生费用；不因进入设置、切换厂商、保存或展开模型列表自动调用。测试使用当前未保存的地址、Key和模型，不保存、不重试、不自动换模型；配置一变化便清除旧结果。

状态区分：未配置、已配置未验证、检查中、验证通过、验证失败。视觉稿采用演示值，不能把“已配置”画成真实连接成功。

## 任务模型

用简洁的四行表单表达当前引擎已有的职责：

| 任务 | 选择内容 | 当前配置对应 |
| --- | --- | --- |
| 创作与规划 | 服务＋文本模型 | model_provider / text_model |
| 关键画面生成 | 服务＋图像模型 | image_provider / image_model |
| 视频审查 | 服务来源＋多模态评审模型 | 现有模型客户端 / video_review_model |
| 视频生成 | 服务＋视频模型 | video_provider / minimax_model |

首期不为每一个Creator／Reviewer建立独立模型设置；多Agent职责与模型接入是两个层次。视频审查沿用现有客户端来源约束，不能将这一行理解为已支持完全独立供应商。

下拉候选来自用户配置和适配器能力。选择不支持的组合时就地说明，不保存为看似可用配置；需要拆分客户端才能支持的组合，明确留作后续改动，不在前端绕过限制。视频模型、分辨率、首帧／首尾帧能力分别展示，沿用当前显式选择，不自动更换。

保存影响后续新启动的任务；运行中的制作保持启动时快照。任务页可查看对应厂商，能直接跳到该服务配置。

## 生成偏好与本机环境

生成偏好只配置现有可解释字段：目标时长、候选数、审查轮次、图像尺寸／质量、视频输出参数。查询间隔、超时、传输方式放在折叠高级区域；没有实际支持的能力不展示可用开关。不增加温度、Top P、模型自动回退、任意角色提示词编辑等当前没有明确需求的设置。

本机环境沿用目录选择、Python、FFmpeg、凭据位置和本地分格／OCR状态，不重复模型服务中的凭据表单。
