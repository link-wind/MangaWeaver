# MangaWeaver 桌面视觉

## 最新视觉方案（2026-11-02，待实施）

见 [视觉设计优化方案](../docs/WORKBENCH_VISUAL_DESIGN_PLAN.md)。该方案结合 UI UX Pro Max 与用户已确认的参考图，细化轻字重、小导航、紧凑附件、首页去顶部标题、媒体优先的画布及对话设计。新一轮视觉实施以该方案为依据；下文保留历史设计记录。方案状态不代表客户端已完成修改。

参考：https://design.minimax.cn/ （2026-10-26 查看官网及其界面样式）。

用户要求整体偏白。沿用工作台的信息架构，将 MiniMax Design 的浅色画布、黑灰文字、紫色强调和克制的圆角应用于本项目；不使用其品牌标识、宣传素材或产品名称。

- 主画布 `#ffffff`，侧栏 `#f7f7f8`，辅助面板 `#fafafb`。
- 主要文字 `#24242b`，说明文字 `#666671`，弱提示 `#777782`。
- 强调色 `#6757e7`，选中背景 `#eeebff`，边线 `#e9e9ef`。
- 按钮及输入框圆角 8～10px，媒体容器 12px；轻边框和低强度阴影区分层级。
- 状态独立表达：绿色通过、橙色待修订、红色错误，文字同时标识含义。
- 系统窗口、原生控件和页面统一浅色外观，不随操作系统深色模式改变。
- 图片与视频保持原始颜色，背景不施加色彩滤镜。

视觉修改集中在 `src/style.css` 与 Electron 的窗口外观设置。模型、任务、数据协议和原有交互流程不受主题修改影响。

## 实机应用参考修订（2026-10-26）

用户明确要求参考安装在 `/Applications/MiniMax Design.app` 的应用设计。通过原生 UI 查看并操作了“项目库”与“开始创作”页面，观察到：全局导航与项目内容分开、浅灰应用外壳、白色大圆角工作区、黑色主按钮、克制的紫色标识、居中创作入口、卡片式内容与可折叠侧栏。未发起生成或上传用户素材。

据此进一步调整：

- 增加“开始创作／项目库”入口，项目内素材／规划／生成／结果采用顶部阶段导航。
- 首页用漫画导入面板承接现有功能；不模拟通用聊天或不存在的模型能力。
- 已挂接运行用可搜索卡片展示，已读取的本地媒体可以用作封面，缺失封面使用明确的本地运行标识。
- 镜头列表采用横向卡片，主区域保留漫画与关键画面对照，审查／反馈独立放在右侧。
- 侧栏支持折叠；黑色主要按钮、灰色选中背景与少量紫色细节替代大面积紫色控件。

当时查看的国际版 MiniMax 本地项目库为空；用户随后切换到中文版并指出已有生成项目。尚未据此验证其项目内画布交互，也没有把其 Skill／插件／ComfyUI 功能加入 MangaWeaver。

## 输入与画布工作流

用户追加要求：首页接受漫画页和 prompt，提交后进入 Canvas，生成中可修改。新增本地附件与多行创作输入；初版采用左侧创作过程／修改输入、右侧可缩放产物画布；后续由用户提供的截图修订，见下。节点可拖动，选中后查看详情并定点修订。生成仍由原三阶段引擎执行。

本次尝试读取中文版 MiniMax（`com.minimax.hub`）的已有生成画布时，应用接口连续超时，曾明确报告 Mac 锁定；用户选择继续使用当前应用接口。用户回复继续后，MangaWeaver 已可正常读取，MiniMax 按当前标识仍超时，按名称则错误解析到旧国际版标识 `com.minimax.hub.global`。当前不将未读取到的参考画布细节当作实测结论，待应用接口可读后再对照。

## 用户截图定稿方向

以用户提供的 MiniMax Design 截图作为画布参考，保留左侧目录和折叠入口，中间为浅灰画布，右侧为创作对话。移除重复标题、常驻流程说明和媒体节点正文，详细信息按需展开。工具栏与底部缩放条采用小型白色浮条，小地图可切换。实际窗口已确认目录、画布、对话同时显示。
