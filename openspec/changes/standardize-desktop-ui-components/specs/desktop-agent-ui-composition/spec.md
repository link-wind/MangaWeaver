## Purpose

使创作对话以一致的输入、消息、任务、工具及子任务展示真实协作过程，让用户理解正在执行、等待审查和等待确认的对象；保留已有流式会话、来源引用、草稿与任务控制，避免外观迁移改变制作事实。

## ADDED Requirements

### Requirement: 首页与对话使用一致的创作输入结构
创作输入 MUST 将文字、紧凑附件／引用和发送操作组织在同一输入区域，保留本地漫画导入、素材选择、目标与参考的区别、制作权限和运行中送达方式；现有发送快捷键与中文输入法行为 MUST 保留。

#### Scenario: 引用节点后继续输入
- **WHEN** 用户从节点菜单添加目标或参考并继续输入中文
- **THEN** 草稿与引用保留原身份，输入法确认不误发送，明确提交后才执行原发送行为

### Requirement: 消息与流式正文保留原轮次
消息展示 MUST 按原会话与轮次追加公开正文，保留编辑历史、重新回答、分支选择与错误归属；界面重绘 MUST 不把同一任务重复显示成多个新任务。

#### Scenario: 正文在任务完成前到达
- **WHEN** 一轮任务分次产生公开正文事件
- **THEN** 完成前逐步显示到原轮次，最终状态依据完成事件更新，不等结束后一次性模拟流式

### Requirement: 任务与子任务体现真实专业协作
任务、工具、子任务和队列 MUST 展示真实对象范围、角色、父子关系、轮次和状态；Creator／Reviewer 的审查、退回修订与再次执行 MUST 可展开追溯。缺失记录 MUST 不推断为通过，也不得展示未提供的内部推理。

#### Scenario: Reviewer 退回后再次创作
- **WHEN** 同一专业任务出现退回与下一轮创作事件
- **THEN** 在同一任务的协作结构下展示角色、轮次和退回依据，当前状态不继承旧通过

### Requirement: 历史阅读与返回最新消息稳定
对话 MUST 在用户阅读历史或展开协作时保留阅读位置，继续接收流式事件，并提供返回最新消息入口；任务列表或正文增长 MUST 不强制跳到末尾。

#### Scenario: 上翻时继续生成
- **WHEN** 用户上翻查看审查而新正文持续到达
- **THEN** 保留阅读位置，用户选择返回最新消息后再恢复跟随

### Requirement: 展示迁移不改变任务执行权限
任务操作 MUST 沿用既有停止、恢复、撤回、引导当前任务和完成后处理语义；查看、展开、切换页面、重开项目 MUST 不隐式提交模型请求或重放工具执行。

#### Scenario: 查看队列后重开项目
- **WHEN** 用户展开待送达要求并关闭后重开项目
- **THEN** 显示真实保存状态，不重复送达要求或重新提交付费任务

#### Scenario: 运行中引导与排队
- **WHEN** 用户明确选择引导当前任务或完成后处理并发送
- **THEN** 按所选方式进入已有处理流程，展示对应送达状态，停止与恢复仍控制原任务
