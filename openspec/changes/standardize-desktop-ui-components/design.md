## Context

动机与范围见 proposal.md。盘点依据为 `docs/UI_COMPONENT_ADOPTION_AUDIT_2026-11-04.md`：App、13 个功能组件及公共组件存在 63 处直接 button、14 处 input／textarea、3 处原生 select 和 21 处 details 定义；这些只是定义位置数，不是待替换实例或完成率。

现有 Electron／React／TypeScript／Vite／Tailwind 4、Radix、React Flow、Lucide 和 Sonner 可继续复用。Python 经受限 IPC／JSONL 提供数据和任务事件。已有 `components/ui/` 尚无完整官方配置与一致主题，不能把新库导入成功等同于迁移完成。

Manga2Animate 是制作引擎参考，不提供当前 Electron 前端的直接替代。保留既有三阶段和 Creator／Reviewer 数据；客户端参考沿用已有 Toonflow 分析。组件结构以官方来源为准，不搬迁参考项目的运行时。MiniMax H3 能力、供应商和模型提示词未受影响，无需为本变更请求付费模型权限或改动渠道。

## Goals / Non-Goals

**Goals:**

- 通用外观与交互由统一组件承担，页面负责业务数据、布局和操作范围。
- 全部 14 类迁移及 Agent 展示覆盖首页、库、画布、对话、设置与专业页；每项有可核对的结果。
- 实际移除重复 CSS、菜单／页签键盘逻辑和分栏拖动代码，保留必要业务组合。

**Non-Goals:**

- 不迁移到 Next.js、不重写 Python Agent、不引入第二套会话、服务或数据库。
- 不扩展模型设置、自动回退、TTS、白板或视频剪辑框架。
- 不以原生标签清零、覆盖率或固定删行百分比为验收指标；不新增暗色主题需求。

## Decisions

### 1. 采用官方 shadcn/ui Radix 版本

配置 `desktop/components.json`、组件路径和语义主题变量，逐项对照官方源码替换现有基础封装。组件与依赖版本、官方源码提交／来源、许可证及必要署名记录在一份文档中。保留现有导出或仅增加薄的业务适配，避免为此次迁移同时重写全部调用协议。

shadcn 默认底层已变化，因此显式选 Radix；读取官方 Radix 对应版本的示例和注册表。来源不可用或不兼容时清楚报出受阻项，不自动切 Base UI／React Aria，不以另写一套仿制控件冒充完成。

对比：Radix Themes 更适合减少本地控件源码，但要更换现有 API 和主题；Mantine 会扩大整体迁移；仅 Radix Primitives 仍需大量自定义样式。本轮按已提出的渐进路线采用官方 shadcn 源码和默认变体，并约束后续自由改写。

### 2. 一套主题与组件变体

沿用白色主界面、轻字重、小导航、细边界和克制阴影。建立背景／文字／边框／品牌／危险／成功／待处理的语义 token，统一字号、控件高度、间距、圆角和焦点样式。普通、紧凑、图标操作使用命名变体；页面不再覆写组件内部结构和尺寸。

迁移时同时清理 style.css／workbench.css 的对应旧规则。允许漫画媒体比例、节点宽度和业务布局样式；保留的原生按钮或 details 记录实际用途。只有重复实现被移除、跨页默认行为一致时才算完成。

2026-11-04 追加视觉收敛：系统字体和日志等宽字体只在 theme.css 定义，弹层与通知也使用同一字体；字号按 11px 元信息、12px 控件、13px 正文、14px 小标题与更高标题层级管理，字重使用 400／500／600。默认控件 32px、紧凑 28px、大号 40px、小型附属操作 24px，通过组件变体指定。旧文件引用同一变量，删除失效声明，不在末尾叠加覆盖。此补充纠正组件迁移完成但视觉尚未完全统一的问题。

布局反馈补充：ActionMenu 默认为 32px 图标按钮，文字入口显式选择普通／紧凑尺寸；项目入口占满目录宽度，避免 CSS 层级使旧尺寸失效。画布两组浮条共用 48px 最小高度和留白，制作控件共用 32px 高度与 16px 行高，按实际画布宽度换行。左栏仅内容区滚动，项目与底部设置固定，已成片的运行不重复列在独立运行中。最小窗口的规划采用镜头条、内容、审查的顺序单列布局，设置采用固定标题和分类、内容内部滚动，视频外层填满预览区域。

### 3. 全部 14 类的落点

| 类别 | 迁移落点 | 选定构件 |
| --- | --- | --- |
| 按钮与提示 | 全部业务页面、媒体操作与工具条 | Button、Button Group、Tooltip |
| 输入 | 首页、对话、搜索、跳页、坐标、对白、反馈 | Field、Input、Textarea、Input Group |
| 下拉 | Planning、会话分支、制作终点、权限、送达方式 | Select |
| 页签与模式 | 右侧工作区、设置、素材筛选、分格编辑 | Tabs 用于内容面板；ToggleGroup 用于模式值 |
| 选择框 | 页面运行选择 | Checkbox，保留 nodrag／nopan |
| 进度与加载 | 节点、媒体、导入、任务 | Progress、Spinner、Skeleton |
| 状态与提示 | 任务、审查、页面错误和完成 | Badge、Alert、现有 Sonner |
| 弹窗与确认 | 设置、选材、引用预览、删除、重新读取 | Dialog、Alert Dialog |
| 会话浮层 | 分支与上下文信息 | Popover + Select |
| 右键 | 节点菜单与键盘入口 | Context Menu，移除手动坐标锚点 |
| 业务折叠 | 协作、候选和核心详情 | Collapsible／Accordion |
| 节点搜索 | 已加载节点的输入与结果列表 | Command／cmdk + Popover |
| 三栏 | 左目录、中央画布、右工作区 | Resizable／react-resizable-panels |
| 左目录 | 导航、书籍分组、设置与页选择 | Sidebar、Item、Separator、Pagination |

首页与成片库的入口共用 WorkspaceHome，分别验收两种模式。MaterialLibrary 与 MaterialPicker、SourceEditor 与 SourceView 都需覆盖，不能只迁移默认渲染分支。Planning、Generation、Results、CandidateHistory 和日志／引用预览属于交付范围。

### 4. Agent 展示采用官方组合，不更换运行时

按官方 AI Elements 的 Radix 对应模式组合 Prompt Input、Message／Chat、Task、Tool、Subagent、Queue。用现有 `turnParts`、任务和公开事件作为输入，继续由现有 handlers 执行操作。仅在两处以上重复时抽出简单展示组件，不添加通用 Agent UI 注册器。

保留 target／reference、中文输入法判断、现有 Cmd／Ctrl+Enter 发送、草稿刷新／关闭前保存、会话分支、权限和消息送达语义。官方样例的浏览器上传、模型选择和 useChat 不是本项目需求，不照搬。作者／审查者、父子任务、轮次、退回原因、真实任务状态均可追溯；不把数据不全的历史记录显示为通过，不展示未提供的内部推理。

流式正文追加到原轮次；用户上翻或展开审查时保持阅读位置，提供回到最新消息。沿用现有会话数据管理；如采用官方滚动构件，删除被替代的滚动监听，不并存两套跟随机制。旧 assistant-ui 仅视口试用已移除，不重新引入它的运行时。

### 5. 分栏与画布的边界

每个布局容器用一个分栏 Group 管理可见面板，条件挂载时维持稳定 id。实施时沿用 App 管目录／主区、CanvasWorkspace 管画布／对话的现有所有权，以嵌套 Group 组合三栏，避免为了压成一个 Group 迁移项目级草稿与画布状态。两处分隔符均由同一开源库处理，不保留手写拖动。把已有 localStorage 像素宽度作为库支持的像素尺寸保留，不创建新的用户配置协议或百分比转换状态。Sidebar 自带宽度状态不得与 Resizable 竞争，不额外显示第二根 SidebarRail。

保留最小宽度约束、无项目时调整、双击复位、键盘调整；分隔线贴区域边缘、无阴影。实际面板尺寸变化继续驱动 React Flow 视图适配，避免重置节点位置或草稿。移除旧 PanelResizeHandle 拖动实现；最多保留必要的旧值读取转换。

拖动缺陷补充：共用 ResizablePanel 在每次挂载时保存初始 defaultSize，不将 onResize 写回的实时宽度反复传给底层 Panel 的 defaultSize。react-resizable-panels 4.18.0 会在默认尺寸变化时注销并重新注册面板，取消当前鼠标手势。宽度继续实时保存，复位及目录折叠使用既有面板 API；对话栏重新挂载时读取最新保存值。

节点右键用真实上下文菜单；Enter／Space 选择、Shift+F10 打开、Escape 回焦及不同节点的删除限制保持。Command 仅管理查询列表交互，现有书页加载和画布命令回执继续负责跨页定位，不扩展成全书搜索引擎。

### 6. 状态、删除与媒体保持事实一致

未知进度为不确定状态，完成为真实完成，不根据时间模拟百分比。普通完成反馈用轻通知；失败、待确认和恢复操作常驻。弹层关闭不误提交任务。

删除继续走已有清理预览与受限 IPC，确认文案保留原始漫画、永久删除生成结果及下游产物的说明，取消先获焦。引用预览接入 Dialog，重新读取接入 Alert Dialog，媒体 lease／release、原生音轨、字幕、候选采用与导出不因展示迁移改变。

## Risks / Trade-offs

- [shadcn 源码仍需本地维护] → 记录来源并以官方组件／命名变体为基线，只保留必要业务适配。
- [旧全局 CSS 覆盖新组件] → 每批迁移同步删除旧选择器，检查弹层、禁用、聚焦、尺寸与小窗口；不叠加末尾覆盖修补。
- [分栏与 Sidebar 竞争、画布手势冲突] → 只设一个宽度来源，保留节点事件边界，在实际客户端检查拖动和最小窗口。
- [会话组件替换丢失草稿／历史位置] → 保留会话状态和组件身份，验证流式追加、历史阅读与关闭重开，不新建消息运行时。
- [官方模式与当前 React／依赖不兼容] → 实施前锁定兼容版本并做小范围编译验证；失败明确记录，不自动换主库或静默缩小范围。
- [已有旧验收尚未完成] → 本变更记录自己的全页验收，旧任务不自动补勾或归档。

## Migration Plan

按“来源与主题 → 基础控件 → 首页／素材／设置 → 画布／分栏 → Agent 展示 → 专业页 → 统一清理与验收”执行。所有 14 类和全部展示模式都是本变更交付范围，分批只是实施顺序。

每批保持项目数据可重开；通过版本控制按批回退代码和依赖即可，无需双组件运行模式、功能开关或业务数据回滚机制。不在验收过程中操作用户的真实永久删除或提交付费任务。

交付时记录：逐页／逐类状态、实际删去的重复实现、合理保留项、依赖来源与兼容结论、构建／现有回归、常用与最小窗口的客户端结果及打包路径。未验项目保留未勾选，不能以打包成功代替交互验收。
