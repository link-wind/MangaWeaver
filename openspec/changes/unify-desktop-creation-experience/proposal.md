## Why

客户端已具备主要制作能力，但画布与旧阶段页面使用两套视觉和操作体系，运行、修订、状态和素材入口重复。先前组件接入仅覆盖局部，无法解决跨页面的认知负担，需要按整个创作流程统一。

## What Changes

- 以画布作为项目主工作区，分格、规划、任务、结果作为专业视图，明确返回与操作范围。
- 统一阶段运行语义，降低重复的调试操作和全局状态噪音。
- 优化首页、成片库、素材库、整本选页、节点详情、对话和专业编辑页面，保留白色简约视觉。
- 统一菜单、弹层、输入、状态与空白页；按需拆出生成任务页面，整理受影响样式。
- 重新评估 assistant-ui 的实际收益：本轮仅使用阅读视口的试接入不值得额外维护完整运行时，恢复项目原有滚动机制；继续使用 React Flow 与本地 Radix 基础组件，不引入新分栏库。

## Capabilities

### New Capabilities

- `desktop-creation-navigation`: 画布与专业视图导航、运行范围、素材与整本选页。
- `desktop-specialist-editing`: 分格编辑、镜头规划、候选比较、视频任务与结果查看。
- `desktop-interface-consistency`: 对话层级、统一菜单、状态、环境设置及简约视觉。

### Modified Capabilities

无；与既有未归档变更的保存、媒体、任务回执合同共同生效，不替代其未完成验收。

## Impact

主要涉及 desktop/src 页面、公共组件、样式及 package 依赖。环境路径单项修改如需扩展，仅增加受限 IPC 参数，保留本地配置格式。Python 制作流程、模型、提示词、供应商、默认分辨率和产物协议不变；默认使用本地样例验收，不提交付费生成。参考现有 Toonflow 分析及 Manga2Animate 固定版本，不迁移其技术栈。
