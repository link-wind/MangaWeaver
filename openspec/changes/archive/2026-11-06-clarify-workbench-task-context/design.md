## Context

见 proposal.md 和 `docs/WORKBENCH_UI_IMPROVEMENT_PLAN.md`。前轮已形成白色三栏及事件式对话，本轮在其上增量修改。制作机制依据 Manga2Animate `29543daacbf58c609c360bad840649b0de6b4866`，复读 `docs/REFERENCE.md` 和既有阶段入口；原 Creator／Reviewer 及 MiniMax 能力检查无变化。

## Goals / Non-Goals

**Goals:** 使用现有 run／page_id／书籍映射表达任务来源，以已有活动及审查事实压缩默认摘要，改善控件的名称和键盘行为。

**Non-Goals:** 不修改后端协议、模型或候选与恢复机制，不建设项目索引，不改变默认权限，不自动付费复跑。保持原稿布局与三栏设计。

## Decisions

1. 在已有 presentation 辅助函数中解析任务归属，传入项目会话和已知运行页元数据。以 run 的确切映射为依据；未知页使用运行名或历史运行，不能从当前页或目录数字猜页码。比按当前页过滤全部历史更能保持项目对话连续。
2. 用已有审查状态和当前轮活动形成短结论；自由文本只限制默认显示，完整内容留在展开区。角色与轮次只读事实，避免额外模型摘要。保留等待问题和恢复操作。
3. 少量共用菜单关闭逻辑统一原生 details 的 Escape、外部点击和焦点返回，不增加菜单库或通用弹层框架。右栏标签使用方向键、Home／End 和 roving tabIndex。
4. 顶部“开始制作”保留 until、节点保留 stage；对话菜单改为能力授权文案，底层 none／planning／images／video 不动。来源提示放在目标与任务卡，避免常驻帮助段落。
5. 成片库为展示更名。已有项目通过现有状态返回画布；没有项目才选目录。沿用既有视频过滤、打开所属项目和实验限制。
6. 集中调整 workbench.css 的文字与状态色、焦点和窄窗口布局，保留无阴影分隔线和用户栏宽。只做与本轮控件有关的样式清理。

## Risks / Trade-offs

- [旧任务页码未知] → 显示运行归属，不猜测；少量纯映射检查覆盖跨页与多书。
- [短摘要隐藏失败／审查依据] → 失败原因与等待问题可见，完整内容可展开，技术数据保留。
- [关闭菜单夺走外部焦点] → 仅 Escape 返回触发器，外部点击尊重用户点击位置。
- [继续项目误触发制作] → 仅切换视图／读取已有状态，实机走查确认无模型调用。

## Migration Plan

无需数据迁移；更新前端包即可。使用隔离配置、本地历史和模拟验收，不停止用户正在运行的制作。交付构建及说明，旧前端仍可读取相同产物。
