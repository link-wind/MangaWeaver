## Context

动机及能力范围见 proposal.md。当前 `agent/loop.py` 等待 `AgentAction` 完整 JSON，再执行工具；主要上下文按最近 24 条消息、10 条结果截取。现有阶段事件已经通过 Python JSONL、Electron 传到界面，但它们不等同于模型文字流。

`tasks.json`、`session.json`、`pending_requests/` 已承担任务、会话与运行中消息存储。专业调用有 TaskBrief／TaskReport 和 Creator／Reviewer 事件，但尚未形成独立可继续的专业会话。保留这些机制、运行目录、产物版本与画布完成回执。

制作流程参考 Manga2Animate `29543daacbf58c609c360bad840649b0de6b4866` 的分阶段、候选与反馈机制。会话交互参考 Toonflow-app `d7366e36ba30943cf308121c28011b45bbf922e0` 的 runtime、sessions、delivery、delegation 和前端 replyStream；借鉴机制，暂不直接复制代码。如需复制，先核对许可证与署名。

## Goals / Non-Goals

**Goals:**

- 让同一轮回复中的公开文字、工具执行、子会话和结果共享可追踪身份，按真实发生顺序呈现。
- 用固定专业角色和少量文件扩展既有执行路径，支持持续上下文、反馈与中断。
- 让压缩、分支和重答具有明确来源，且不会重放制作操作。

**Non-Goals:**

- 不迁移到通用 Agent SDK，不增加服务、数据库、插件平台或任意角色递归。
- 不改变三阶段制作协议、供应商选择、候选数量或 Reviewer 权限。
- 不借本次改动验证或替换视频后端。H3 输入能力与原有显式配置检查继续有效；本轮验收不默认调用付费生图／视频。

## Decisions

### 1. 扩展现有 JSONL 协议，保持单一执行写入方

在现有事件通路增加稳定的会话、分支、轮次、尝试、内容块、调用和父调用标识，以及事件 ID 与顺序号。短期 IPC request_id 仅标识传输请求，不充当持久化轮次身份。工具事件同时带任务、运行目录和输入版本来源。

事件覆盖文字开始／增量／结束、工具准备／开始／进展／结果、子会话提问／交回、消息接收、上下文统计／压缩及轮次终止。保留既有阶段事件供画布使用，嵌套客户端调用不得重复生成相同工具卡片。

执行进程是历史的唯一写入方；收件箱仍使用已有短锁接受或撤回消息。先持久化再推送，文字增量可合并为小段写入。界面按身份归并并批量渲染增量，不为每个片段创建消息，重复事件不重复展示。

选择扩展 JSONL 而非建立新 HTTP／WebSocket 服务，因为现有本地链路已支持事件传输，问题是事件内容与身份不足。

### 2. 真实流式读取与完整动作校验分开

在现有客户端直接增加流式入口，不增加客户端抽象基类。优先验证当前显式配置的幻灵 `gemini-3.8-flash` 及其实际传输方式；检查 SSE、结束标记、HTTP 200 内错误和断流。其他配置渠道按对应协议实现，不静默替换渠道、模型或请求模式。不支持时明确报错，不使用打字动画假装流式。

统一 Agent 初期继续沿用 `AgentAction` 结构。增量解析器仅释放已经确认属于公开 `text` 字段的内容，正确处理跨片段 JSON 转义和 Unicode；不展示整个 JSON、隐藏思考或未校验参数。动作及参数必须在完整响应结束并通过原有数据校验后才能执行。截断响应保留公开文字，但不执行残缺动作。

专业候选和审查仍以完整且校验通过的原始产物结构为准，部分输出不能提前成为画布可用产物。公开执行说明与最终提交可分为同一角色会话的不同块，不新增用于播报进度或总结的额外模型调用。

选择保留结构化动作而非把文本流直接解释成工具指令，以降低协议变化并保住执行边界。只有实际供应商首段早于最终完成到达，才算真实流式验收通过。

### 3. 对话轮次承载实际工具生命周期

工具以稳定 call_id 关联调用前公开说明、经校验参数、实际进展和终态。准备完成、已提交远端、产物落盘、审查通过和画布操作完成分别记录；后续事件出现不意味着前一步成功。没有真实进度时只显示运行状态，不推算百分比或时间。

停止需要终止本地流连接／请求子进程并禁止下一次工具执行。远端视频提交是否取消遵守原接口能力，保留原任务 ID；无法确认提交结果时先查询原任务，不重复提交。重试使用独立 attempt_id，保留前次中断内容；不承诺从任意 token 续传。

选择基于实际事件更新工具块，而非由前端根据时间或下一条消息猜测状态，以维持画布与会话一致。

### 4. 固定专业会话复用原 Creator／Reviewer

为既有脚本、编排、演出、故事板 Creator／Reviewer 及实际存在的视频审查角色建立独立子会话，默认顺序执行。身份包含父会话、分支、任务、角色、目标及输入签名。输入未变的反馈修订可继续相同角色上下文；输入版本改变必须显式切换有效上下文，不能混入旧候选。

角色只获得当前任务所需工具：读取指定来源／反馈、向父会话提问、提交候选或提交审查。Creator 不能自行批准，Reviewer 不能绕过原审查结果；文件处理仍是工具。禁止任意代码、任意文件读写、自由递归委派和自行付费生成。

最小改造专业调用入口：原先一次专业模型请求成为对应子会话的一轮，增加受限动作与最终提交封装；最终候选／审查仍校验原 schema，调用原写入、选择及反馈路由。避免在原 Creator 外再套一个策划模型、然后重复调用 Creator，也不额外调用报告模型。

提问带子会话、分支、问题和输入版本身份，由父会话展示并等待真实回答；回答只进入该会话。交回报告引用实际产物与审查状态，不能替代 Reviewer。子会话行动限额、原反馈轮数和父任务预算均有限，续接不能重置预算。

父任务停止会中断活动本地子调用；已提交远端任务保留恢复身份。重开项目只读取历史，不自动重启父子任务。

选择固定角色会话而非通用多 Agent 框架，因为职责、交接点和制作协议均已明确。

### 5. 活动消息在安全边界进入对应会话

复用现有收件箱、目标快照和撤回机制。当前引导绑定接收时的分支、任务、专业角色、页与输入版本，在下一模型／工具边界接收；不声称改变已提交请求。文本问题走只读回答；影响产物的修改仍走既有显式修订与审查路径。

后续要求拥有独立轮次与稳定任务 ID，只有当前任务真实完成且授权仍有效才继续。停止、失败、待回答和重新打开项目都不会自动清空队列执行。收件分类完成前再次检查撤回与版本，避免已撤回内容进入模型上下文。

问题回答按问题 ID 定位原子会话，不按界面最新选中对象推断。旧分支／旧版本问题明确提示重新定位，不转发到当前镜头。

选择保留文件收件而非另建消息总线，补齐接收与消费语义即可满足本地单执行任务。

### 6. 按会话构造上下文并保留可追溯摘要

将供应商实际 usage、估算输入及未知值分开。渠道别名无法确定容量时读取显式配置；不虚构精确百分比、容量或金额。媒体以真实引用和必要输入进入上下文，不能每轮重新附带整本漫画。

上下文由当前分支、固定系统约束、用户目标与权限、活动任务／问题／收件、当前版本引用、相关摘要及近期完整工具组构成，替代仅按消息数量切片。工具调用与结果成组，避免丢失对应关系。

摘要记录来源区间、分支头与校验信息，原文永远保留。结构化摘要包含原作事件、配色／对白决定、未通过审查、未完成问题、版本与远端任务身份。权限、状态和任务 ID 由确定性数据单独固定，不能由模型摘要改写。摘要叙述可由同一配置文本模型生成。

只在已启动的文字任务内按预算触发压缩，或用户显式点击压缩；浏览、重开及切换分支不调用模型。压缩失败保留原历史，无法容纳输入时明确停止，不静默删历史或换模型。

选择摘要加真实历史索引而非向量数据库与长期记忆服务，因为当前需要解决项目会话长度和追溯。

### 7. 分支保存对话差异，不重放制作副作用

使用简单分支元数据：id、父分支、分叉消息、当前头。编辑历史消息后发送、重新回答生成新分支，原分支及产物保留；仅创建或切换分支是只读动作，显式发送才开始文字轮次。

消息、摘要、问题、收件及子会话归属分支。存在活动执行时，先明确停止或等其完成再切换，不能将结果写入新分支。历史工具结果仅作可追踪引用，不作为自动执行脚本。

引用旧产物不等于修改或回滚文件。重新制作走原有显式修订运行及审查；重答或分支不得自动重放之前的生图／视频提交。复用产物标明实际来源，恢复远端任务继续使用原 ID。历史授权记录不自动扩大新分支的制作范围。

选择简单父分支索引而非通用依赖图，明确当前需求只涉及对话分叉和现有运行版本。

### 8. 文件存储和界面保持收敛

保留 `session.json` 当前视图索引、`tasks.json` 任务事实、`pending_requests/` 收件以及原运行产物。按需新增项目级 `conversation.jsonl` 保存有序内容块及事件，`agent_sessions/` 保存分支与子会话索引，不重复保存一套制作状态。

右栏以一轮连续内容为主，工具和子任务默认折叠，展开可看参数、进展、问题与报告；上下文用量和分支入口保持简短。运行详情不占据主要回复区域。老记录只展示已有事实，不补造历史文字流或专业决策过程。

## Risks / Trade-offs

- [当前中转不支持真实流式] → 首先以最小真实文字请求验证；失败保留明确阻塞结果，不以本地模拟代替供应商验收。
- [增量 JSON 解析错误导致提前执行] → 仅公开文字允许增量展示；完整校验是执行硬边界，并检查跨片段转义、截断及结束错误。
- [子会话造成调用数量膨胀] → 复用原角色模型调用与产物提交，禁止额外播报／报告模型，保留原反馈限额。
- [摘要丢失拒绝意见或扩大权限] → 确定性固定权限、版本、问题与任务身份，摘要带来源，失败不丢原文。
- [分支重复付费提交或错写版本] → 分支不重放工具，实际制作仍按原目标检查、任务恢复与显式修订路径执行。
- [新旧客户端协议混用] → 记录格式版本，首次写入前备份，旧数据只按可证实内容迁移；不能理解新格式的客户端禁止继续写入。

## Migration Plan

1. 先验证真实供应商流，随后实现事件身份与存储、文字流和工具块，保留原制作调用入口。
2. 接入固定专业会话与活动消息，再补上下文压缩及分支；所有六项均属于本变更，不能在只完成气泡流式时标记整体完成。
3. 首次升级项目备份既有会话／任务文件，明确格式版本。原始运行路径、根目录注册运行 `runs: ["."]` 和远端恢复身份保持可读。
4. 回退客户端前恢复备份会话索引，升级后产生的新对话文件保留只读；不通过回退删除产物或撤销远端任务。
5. 用少量协议检查、本地真实 SSE 测试及原生客户端走查验收；真实渠道文字流单独记录证据，不能以 Mock 或整段输出替代。默认不重新执行付费媒体生成。
