## Purpose

让用户能从历史要求继续另一种方案，编辑消息、重新回答和切换分支时保留原来的讨论与成果。会话分支只改变对话路径，制作修改仍经过明确授权和现有运行版本机制，不自动重放旧工具调用。

## ADDED Requirements

### Requirement: 编辑和重答保留原分支
用户 MUST 能从历史用户消息编辑后发送或请求重新回答，形成拥有稳定父消息和分叉点的新分支。原消息、原回复、工具记录与产物 MUST 保留。分支创建与切换本身 MUST 不执行模型或制作；明确发送或重答才启动对应文本轮次。

#### Scenario: 修改旧要求
- **WHEN** 用户把历史要求从偏快节奏改为保留更多停顿并明确发送
- **THEN** 系统创建新分支并按当前授权处理新要求，原分支和已生成动画仍可查看

### Requirement: 分支上下文与待办隔离
消息、摘要、问题、专业子会话、待处理请求和任务 MUST 具有明确分支归属。选择一个分支时 MUST 只使用其有效历史与显式引用，不将其他分支的后续对话、权限或任务自动加入。执行期间切换活动分支 MUST 先明确停止或完成当前执行。

#### Scenario: 两个分支有同名镜头
- **WHEN** 用户在新分支修改第二镜头，而旧分支还有同名目标待办
- **THEN** 修改只针对新分支绑定的运行版本，旧待办不出队、不修改另一分支

### Requirement: 会话分支不复制制作副作用
分支和重答 MUST 不重放已保存工具调用，不把旧远端任务当新任务重新提交。需要改变制作产物时 MUST 沿既有显式修订运行及审查，复用只读产物时保留来源和版本；恢复下载继续使用原任务身份。

#### Scenario: 从视频提交前的消息分叉
- **WHEN** 用户在历史视频提交前的消息处创建分支或重新回答
- **THEN** 原视频任务仍可追溯，分叉不自动重新提交；额外制作须有当前明确目标和相应授权
