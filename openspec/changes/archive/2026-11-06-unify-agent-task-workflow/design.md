## Context

动机与范围见 proposal.md。本变更跨越 Agent、专业流水线、JSONL 与创作栏，涉及持久化和中断语义，需要技术设计。

现状：`agent/loop.py` 保存 session.json 并以结构化动作调用工具；`agent/stages.py` 的按钮入口直接执行同一专业工具。`planning/pipeline.py` 已有按阶段暂停、定向反馈、有限轮次和文件检查点，Creator／Reviewer 是实际独立模型调用。`generation/pipeline.py` 已保存远端任务身份并区分提交、查询、下载与评审。右侧 `CanvasWorkspace.tsx` 先列消息再列日志，`runtime.ts` 会根据阶段切换推断部分记录完成，尚不足以表达角色与修订关系。

参考基线仍为 Manga2Animate `29543daacbf58c609c360bad840649b0de6b4866` 的 run_all.py、create_script.py 及相关分镜审查流程；复用其已有候选、专业反馈和文件恢复，任务身份与桌面投影属于 MangaWeaver 增量。实施前复读对应代码并更新 docs/REFERENCE.md，不直接迁入缺少许可证授权的代码。

## Goals / Non-Goals

**Goals:**
- 用薄的任务记录和协调入口连接已有 Agent／工具，使消息、专业协作、画布和恢复引用同一业务身份。
- 在现有有限反馈循环内显式记录提交、审查和退回，不重写专业模型调用。
- 当前客户端活动期间连续执行已授权目标，允许安全提交修改，并明确处理停止与重开。
- 右侧保持白色、简洁、小摘要与折叠详情，不增加常驻大段解释。

**Non-Goals:**
- 不增加多 Agent SDK、独立 Agent 服务、数据库、通用 DAG、插件体系或无限自治。
- 不调整镜头生成方法、OCR 后端、模型渠道、分辨率或自动付费重生成规则。
- 不把 Lite／480P 可用性作为验收条件；保留现有能力校验，不能静默改配置。
- 不建设后台无人值守任务、跨项目调度、通用时间线搜索或独立混音系统。

## Decisions

### 1. 任务是协作单位，沿用现有串行执行器

在 `agent/` 增加少量任务读写与协调函数，按职责最多拆为 tasks.py 与 workflow.py，不新增抽象基类。总 Agent 保持理解和选择受限工具；专业流水线继续拥有专业反馈循环。采用“父制作任务 → 阶段子任务 → Creator／Reviewer 轮次记录”的固定层级，不允许任意嵌套编排。

所有制作入口先登记任务，再调用现有工具。阶段按钮直接建立单阶段任务，不为机械运行增加总 Agent 模型调用；自然语言请求由总 Agent 确定目标、范围和所需前置任务。两者共享执行校验、结果、停止和恢复。只要求查看或回答时仍可直接回复，不强制生成制作任务。

未采用替代方案：仅给日志加角色标签无法恢复真实任务；换新多 Agent 框架会重复现有阶段实现。

### 2. 少量文件保存任务身份，业务内容仍以既有产物为准

项目级 tasks.json 保存任务快照，沿用现有原子文件写入与文件锁。每个任务包含：
- task_id、parent_id、请求／消息关联、创建顺序与时间、入口；
- page/book、run、目标业务 ID、输入版本／签名、目标终点；
- 授权制作范围及其来源、状态、暂停原因和结构化可用操作；
- 专业阶段、actor、role、迭代／attempt 标识、产物和审查文件引用；
- 最近进展和已消耗的业务修订／决策预算。

会话保留消息与 active_task_id，不复制全套任务和审查数据。远端 task_id 仍以现有 generation tasks 文件为依据，任务记录只引用；不会用新 task_id 取代供应商 task_id。

任务使用有限状态 queued、running、waiting_user、failed、interrupted、completed；原因另存，如 missing_input、scope_required、review_exhausted、dependency_missing、transport_error、version_conflict。Creator 的提交完成不等于专业任务完成；Reviewer 调用成功且结论拒绝时，记录“审查已完成／结论退回”，父任务继续修订或等待处理。远端排队、生成、下载状态与父任务状态分开。

新任务快照是执行状态依据，产物和审查文件是内容依据。写完必要产物与检查点后才记录完成并发出事件；启动恢复遇到未结束任务时核对文件并标明中断或待恢复，不从单个文件存在推断完整通过。旧 runtime_events.jsonl 保留作过程记录，不作为完成猜测来源。

### 3. 制作终点和授权属于任务，阶段暂停属于执行策略

目标阶段固定沿用分格、脚本、编排、演出、关键画面、视频成片。自然语言连续任务使用“执行至终点”策略；单阶段按钮使用“仅此阶段”策略。前者在已有授权内补齐依赖并连续推进，后者缺前置就返回明确阻塞。动作演出对无动作镜头显示“不需要动作演出”，不伪造 Agent 产出。

对话输入保留一个简洁的制作范围入口，如本地处理、规划、关键画面、成片；页面／目标显示为可移除引用。范围保存在任务授权记录，工具每次实际校验；模型文字不能修改授权。超出范围时显示将执行的工作和明确操作，确认后更新当前任务，不要求去寻找多个权限开关。单阶段按钮本身授权该阶段，与同类对话任务共享规则。

阶段检查点仍保存，但在连续目标中通过审查后不因 pause_after 机械等待用户；单阶段任务在该阶段结束即完成。正常目标终点、等待用户和专业拒绝必须使用不同状态与原因。

### 4. 内部续接由活动客户端执行，保持有限预算

现有每请求有限工具步数保留为执行批次。批次结束后保存 active_task_id、已执行结果与预算，返回可续接标记。Electron／前端只在同一活动任务、授权未变、没有停止或待处理冲突时发起下一批请求；该入口只读已有任务，不再次添加用户“继续”消息、不扩大范围。画布回执继续使用现有 call_id／revision 校验。

批次续接不重置专业修订次数和父任务总决策预算；重复同一失败、无有效进展或总预算耗尽时明确停止并解释实际阻碍，不靠自动继续无限转圈。停止或重开不续接。显式恢复先核对原检查点和任务 ID，不重新提交状态不明的付费请求。

未采用常驻调度进程：现有单次 JSONL 请求已能承载批次，活动客户端续接足够满足本轮。

### 5. 在真实模型与工具边界记录专业协作

在现有 script、arrangement、direction、storyboard、dialogue、video review 调用和返回处增加可选的任务事件上下文，CLI 无订阅者时不受影响。事件携带 task_id、parent_id、page/run、actor、role、iteration、attempt、target 和产物／审查引用，使用明确的 started、submitted、reviewed、revision_requested、completed、failed 边界；传输失败有独立原因。

角色标签为固定专业职责，不新增独立模型配置：脚本 Creator／Reviewer、编排 Creator／Reviewer、演出 Creator／Reviewer、关键画面 Creator／Reviewer、对白 Creator／Reviewer、视频 Reviewer。总 Agent 记录委派和汇报；MAGI、视频生成、下载及剪辑显示工具名称。脚本的角色审查和逐格审查可归组，但保留真实子目标。

沿用现有 ReviewReport 的 target、location、evidence、suggestion 生成短摘要，提供原审查详情；不额外调用模型生成“Agent 互聊”，不保存或展示私有思考。缓存复用记录 reused 和原产物引用，不能显示新生成或新审查。

保留现有整体反馈路由，记录某轮反馈如何退回上游，以及下游何时重新执行／复用；不新增自动失效图。生成后的视频审查拒绝仍保留候选并等待明确操作，不为展示循环自动加一次付费视频。

### 6. 运行中的修改进入本地收件区，在安全边界处理

当前会话锁可能覆盖长模型调用，因此不能另起 agent_message 并发改 session.json。新增受限的本地“提交／撤回修改”入口，向项目 pending_requests/ 按 request_id 原子保存一项请求；该入口不调用模型、不持有制作锁、不改活动 session 或任务输入。请求绑定父任务、页面、run、目标、基础版本和提交顺序；用户可在被接收前撤回，请求文件的状态修改受短文件锁保护。

现有执行器是唯一消费者。在当前模型／工具返回并保存真实结果后、下一受影响工作启动前检查请求。没有完整阶段检查点时先保存原始候选，候选仍未通过；只有可恢复边界才能交接。修改进入已有 fork_canvas／from_stage／location 路径，由总 Agent 或专业任务处理；不会在运行中的输入上就地覆写。

有待处理修改时先停止原目标继续扩展，按顺序处理一项；后续请求逐项核对版本，存在冲突就等待用户选择，不自动合并或套用到另一页。明确修改授权仅覆盖该要求及当前已授权制作范围，额外生图／视频按范围检查。处理结果记录 applied、withdrawn 或 needs_decision，继承任务关联与来源版本。停止后请求保留，只有用户恢复才消费。

这是单活动任务的本地收件区，不是后台消息队列或并行调度系统。

### 7. 右侧以统一时间线呈现，工具详情默认折叠

将创作栏从 CanvasWorkspace.tsx 按职责抽出时间线、任务卡和输入组件，画布布局保持不变。时间线按持久化顺序合并用户／助手消息、明确阶段操作与关联任务；任务卡随状态更新，不为每个轮询生成气泡。阶段按钮使用“运行·镜头编排”操作条目，不向会话伪造自然语言用户消息。

任务卡默认显示名称、页／镜头、当前 actor、状态、短摘要和必要操作；展开才出现角色提交、审查依据、反馈轮次、旧版本引用和技术错误。独立视频候选显示各自真实状态。顶端仅保留当前制作和停止入口；底部保留目标引用、范围和输入，不再重复展示整块运行日志、技术阶段选择和多处权限。

卡片的下一步操作由后端结构化返回，如补充输入、前往前置阶段、确认范围、查看问题、恢复查询／下载、恢复本地任务；前端不从自然语言猜按钮。运行状态无可靠进度分母时用明确阶段，不捏造百分比或 ETA。

任务与节点通过 run＋业务 ID 关联。点击产物复用已有 control_canvas 和完成回执，先展开书籍／阶段组；旧版本先打开对应运行，不能用同名节点替代。节点详情展示关联任务入口。多页任务按父制作任务分组，每个子任务有页码；页面切换不改变活动任务目标。

### 8. 兼容与错误边界

旧 session、canvas 和运行产物保持可读。仅首次明确运行新任务时建立新的任务记录；没有真实角色信息的旧日志显示为折叠“历史记录”，不补造轮次。已有审查文件仍可查看。任务记录使用可选版本字段兼容旧项目，不批量迁移已生成内容。

错误沿用当前明确配置、有限网络重试与防重复提交。内容修订由 Creator／Reviewer 执行；传输错误不改写内容；未知提交保持需核查状态。任务摘要、收件内容和事件写入沿用密钥脱敏，模型返回文本是资料，不能自行授予权限或执行任意代码。

## Risks / Trade-offs

- [任务快照与产物更新中断] → 先保存产物和检查点再发布终态；恢复核对真实文件，缺证据保留中断，不构造跨文件事务框架。
- [活动客户端重复续接] → 复用现有项目／运行锁和 task_id／revision 校验；停止标记在每批执行及远端提交前检查。
- [修改收件与撤回竞争] → 短锁下认领单项请求，已认领后不能假装撤回；明确展示处理状态，不并发修改会话。
- [角色事件过多使创作栏更乱] → 卡片聚合阶段与轮次，默认只显示当前摘要，技术日志折叠，避免轮询刷屏。
- [视频原任务恢复和新增重生成混淆] → 两种操作明确分开，恢复只使用旧 ID，额外付费生成显示新范围并由用户启动。
- [旧规范尚未同步主规范] → 本变更独立新增两项能力，并在文档明确替代早期交互决定；归档时保留新任务推进语义，不复原旧步数／草稿交互。

## Migration Plan

1. 先复核参考实现、既有防重和停止语义，完成任务协议、文件保存和专业事件，不改变生成算法。
2. 让对话与单阶段入口共用任务记录，接入明确终点、批次续接和恢复操作；旧项目继续可读。
3. 接入待处理修改的本地入口与安全边界消费，再替换右侧时间线和输入区。
4. 用现有本地模拟任务扩展最小专业反馈预设，显著标为模拟，验证退回／通过／失败／中断，不把模拟当作真实模型成功。
5. 原生客户端走查正常推进、单阶段、反馈、修改、停止、重开、原任务恢复和画布定位。付费模型验证只有后续明确启动时执行；本变更默认不新增付费调用。
6. 更新使用文档、参考记录和实际验收范围；保留旧版本与旧产物，不删除用户资料。
