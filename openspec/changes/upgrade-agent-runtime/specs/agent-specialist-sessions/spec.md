## Purpose

让现有专业 Creator／Reviewer 拥有可持续的任务上下文和有限执行过程，能够读取必要资料、提出具体问题并交回结果。专业协作继续服务漫画制作，保留原有候选、审查、有限修订和来源追溯约束。

## ADDED Requirements

### Requirement: 固定专业角色的独立会话
专业委派 MUST 建立关联父任务、分支、专业角色、目标和输入版本的独立会话，保留本专业的资料、动作、反馈和结果，支持明确继续同一会话。专业角色 MUST 能按职责使用有限读取、提交或提问动作，而非仅增加角色名称与状态标签。

#### Scenario: 编排 Creator 继续修订
- **WHEN** 编排候选被 Reviewer 退回且目标与输入基线仍有效
- **THEN** Creator 在自己的会话中取得该候选和实际问题继续修订，不重置业务轮次、不混入其他角色聊天

### Requirement: 原有专业审查职责保持有效
Creator MUST 不自行给候选标为审查通过，Reviewer MUST 保留原结构化结论与依据；总 Agent MUST 不覆盖拒绝。专业会话 MUST 沿已有阶段依赖和有限反馈推进，确定性工具不改为 Agent，不能任意递归委派或扩大工具权限。

#### Scenario: Reviewer 发现上游错误
- **WHEN** 关键画面 Reviewer 认为问题来自脚本
- **THEN** 子会话交回具体上游问题，由总 Agent 在现有授权内协调，不由 Reviewer 自行重写脚本或调用额外视频生成

### Requirement: 提问和回报连接真实任务
子会话 MUST 能向父会话交回明确问题、阻塞或最终报告。需要用户回答的问题 MUST 关联原子会话、目标和输入版本；回答后继续正确子任务。报告 MUST 引用真实产物与原审查，不得以建议代替执行授权。

#### Scenario: 缺少角色配色资料
- **WHEN** 专业任务需要用户确定配色且已有资料不足
- **THEN** 父会话显示该子任务的问题，答复绑定原问题后继续，不把整页所有任务重跑

### Requirement: 父子生命周期一致
父任务停止 MUST 阻止活动子会话继续发起模型或工具调用；已提交远端工作按现有规则保留。子会话的完成、等待输入、限额、失败和中断 MUST 如实传给父任务和界面。重开 MUST 不自行恢复子会话执行。

#### Scenario: 子任务运行时停止父任务
- **WHEN** 用户停止正在等待专业任务的总 Agent
- **THEN** 本地专业执行停止、部分记录保存、父子状态一致，没有子会话在后台自动开始下一次生成
