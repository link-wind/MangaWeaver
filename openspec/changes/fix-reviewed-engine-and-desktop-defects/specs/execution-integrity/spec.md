## Purpose

保证桌面和 CLI 在既有本地运行机制下正确识别候选、保护并发草稿、独立保存修订素材并报告执行失败，让用户能够保留中间产物并明确恢复，而不会因文件命名或锁层级差异中断正常制作。

## ADDED Requirements

### Requirement: 候选与状态文件分离
系统 MUST 仅将完整候选记录作为可查看或采用的候选，不把任务与响应记录解释为候选。

#### Scenario: 生图留下状态文件
- **WHEN** 候选图片旁同时存在任务、响应和正式候选记录
- **THEN** 查看与采用仅处理正式候选，继续执行已有来源和审查校验。

### Requirement: 执行和草稿边界
系统 MUST 允许同一调用链操作原地运行并拒绝竞争执行；清理草稿 MUST 校验提交时版本，保留并发编辑。

#### Scenario: 原地运行与并发草稿
- **WHEN** Agent 已持有项目锁并调用同目录专业阶段，或用户提交后继续编辑草稿
- **THEN** 专业阶段不会自锁；新的草稿不会被旧提交清空。

### Requirement: 失败准确报告
系统 MUST 通过失败协议报告非法参数与模型解析错误；审查退回 MUST 根据明确原因分类，不依赖异常文案。

#### Scenario: 非法模型输出
- **WHEN** 模型输出无法校验或命令参数非法
- **THEN** 返回明确执行失败，不能静默退出或冒充用户决策问题。

### Requirement: 修订素材独立
修订运行 MUST 独立保留复用的关键画面，且不复制已提交视频任务。

#### Scenario: 删除旧运行关键画面
- **WHEN** 用户建立修订运行后删除旧运行的生成图片
- **THEN** 新运行的保留关键画面仍可读取并保持内容签名。
