## Why

当前右侧将对话、阶段日志、权限和错误混在一起，用户难以判断谁在工作、为什么修订、何时需要介入。专业 Creator／Reviewer 已存在，但其协作过程缺少任务身份和真实交接记录；自然语言与阶段按钮也缺少一致的进度与恢复语义。

## What Changes

- 统一创作请求与阶段按钮的任务记录和执行入口，明确目标页面、版本、制作终点与已授权范围；保留精确的单阶段运行。
- 创作 Agent 负责理解、委派和协调；阶段 Creator／Reviewer 保持专业创作与有限反馈循环；分页、MAGI、下载和剪辑保持工具职责。
- 在阶段内部记录 Creator 提交、Reviewer 审查、反馈修订与上游退回，关联实际产物和审查依据，不模拟 Agent 发言。
- 右侧改为按发生顺序排列的对话与任务卡片；默认展示简短摘要，展开查看角色、轮次、审查和错误，支持与画布节点双向定位。
- 已授权的连续制作通过审查后自动推进到指定终点；信息不足、范围变化、内容修订耗尽和执行失败分别展示对应操作。
- 运行中可提交绑定目标的待处理修改，在步骤安全边界处理；停止、重开和恢复保留版本与远端任务身份，不重复付费提交。
- 用项目内少量文件保存任务和待处理请求，替换界面通过阶段切换猜测完成的方式，沿用既有产物、文件锁和 JSONL 机制。

## Capabilities

### New Capabilities

- `agent-task-workflow`: 统一任务身份、制作范围、阶段交接、专业反馈循环、待处理修改及中断恢复。
- `agent-collaboration-timeline`: 右侧统一时间线、专业角色任务卡片、当前状态与下一步操作、画布联动。

### Modified Capabilities

无。当前 `openspec/specs/` 尚无已同步主规范；以上能力以增量规范新增，并明确更新早期创作 Agent 变更中“内部步数到限需用户继续”和“运行中只能保存草稿”的交互决定。已有会话、画布回执和专业阶段能力继续复用。

## Impact

涉及 `agent/loop.py`、`agent/stages.py`、`agent/tools.py`、阶段流水线的事件边界、`events.py`、必要的数据协议与桌面 JSONL／IPC，以及右侧创作栏、运行状态投影和节点详情。复用 Manga2Animate 已参考的阶段、候选、Creator／Reviewer、反馈路由和文件恢复，不增加多 Agent 服务、数据库、通用工作流框架或新模型依赖。

本轮不调整漫画转动画算法、不新增自动付费重生成，不验证或变更 Lite／480P 与其他后端配置；用户已将该后端验证移出本轮范围。验证以本地任务流程和原生客户端走查为主，不因本提案发起付费生成。
