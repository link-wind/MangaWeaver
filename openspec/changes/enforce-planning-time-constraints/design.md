## 设计决定

### 说话人阻断放规划流水线，不放 SourceScript schema

三个备选位置中：

- SourceScript 模型校验器／`check_source` 直接禁止 null：会在**加载**任何含 null 对白的历史产物（草案、production.json）时崩溃，破坏只读路径；且 `json_to` 无重试循环，Creator 无法在同一阶段内自我修正。
- dialogue.prepare 保持现状：即审查发现的死锁——分配与省略两条路都被封死，发生在图片付费之后。
- 规划流水线在脚本阶段收口处检查，命中即合成一条 `scope="script"` 的拒绝审查并走既有"保存草案＋反馈＋下一轮"路径：复用现成反馈机制（Creator 下一轮带着归属要求重写脚本），真正无法归属的台词在轮次耗尽时 `ReviewRejected`，发生在任何图片支出之前；不破坏历史产物加载。

提示词同步把"无法确定用 null"改为"归属最可能发声角色＋uncertainties 记录推断"，与 PROJECT_GOALS 3.1"区分原作提供信息与系统推断"一致：归属是推断不是发明对白内容。后续若实现台词"有意省略"表达位，此门槛可放宽为"null 必须配省略决定"。

### 段长常量放 schemas，不进 config

- schemas 是跨阶段协议层，段长属于"产物必须满足的后端契约"；clients 单向导入 schemas 方向正确（反向会让协议层依赖环境配置）。
- `config.py` 当前有进行中的未提交改动（模型服务设置），本变更只做纯增量，避免合并冲突。
- 常量同时供三处使用：schemas 内校验、minimax 提交前校验、四个提示词载荷的规则文本。若未来更换视频后端，再把常量提升为配置，属显式变更。

### 校验下沉到 check_source／check_shot 的代价

历史运行中静态时长不合规或锚点差越界的草案，在显式重跑（from_stage）与 ProductionPlan 重建时会被拒绝并明确报错；不自动迁移、不放宽旧数据。这符合项目"显式重跑、不静默兼容"的约定。

### 顺序游标取 max

`last = max(indices)` 后：

- 交错 S1=[p01,p03]、S2=[p02,p04]：S2 的 min=1 < S1 的 max=2，拒绝。
- 嵌套 S1=[p01,p04]、S2=[p02,p03]：S2 的 min=1 < 3，拒绝。
- 共享格接续 S1=[p01,p02]、S2=[p02,p03]：min=1 ≥ max=1，通过。
- 同格拆分 S1=[p01]、S2=[p01,p02]：min=0 ≥ max=0，通过。
- 真回跳 S1=[p03]、S2=[p01]：拒绝（原行为保留）。

### 总时长复查的三个接入点

编排候选生成时已有内联检查（保留语义，换用共享助手）；新增规划完成写 production.json 前、恢复检查点写 production.json 前、视频任务构建前三处。手改 production.json 绕过规划的场景由视频任务构建前的检查兜底，全部发生在任何付费提交之前。
