## Context

动机见 proposal.md。界面和工程设计依据为 `docs/TOONFLOW_INSPIRED_DESIGN.md`、`docs/TOONFLOW_ENGINEERING_REFERENCE.md`。用户确认两者一起规划、分批实施。

当前 Electron／React／React Flow 通过受限 IPC 与 JSONL 连接 Python。已有 50ms 流式批处理、按分支与 sequence 归并、运行文件锁、任务 ID 恢复和画布完成回执；这些机制继续使用。当前 `write_json` 使用固定临时文件名，媒体 token 没有配对释放入口；编辑草稿已有防抖和内存缓存，但切换前等待持久化需补齐。

Toonflow 参考的是用户提供的本地源码，关键指纹与 MIT 许可在上述参考文档中记录。Manga2Animate 仍以 `29543daacbf58c609c360bad840649b0de6b4866` 为三阶段与候选审查参考。本轮是桌面交互及保存增量，不改生成提示词、模型、重试、H3 请求或默认能力；不需要为本轮设计发起付费 H3 能力测试，也不声称未验证的 Lite／480P 已可用。

## Goals / Non-Goals

**Goals:**

- 用现有页面与状态承载选材、节点编辑、协作查看及候选浏览，减少重复层级。
- 为编辑保存建立版本、所有者与完成边界，避免旧请求覆盖新草稿。
- 为本地媒体访问建立可回收的生命周期，保留授权与视频 Range 读取。
- 以少量关键回归检查和本地客户端场景形成可核实交付。

**Non-Goals:**

- 不迁入 Vue／Bun／Express、通用插件框架、数据库、复杂读写调度或自动合并系统。
- 不加入模型渠道管理、余额、充值、云端市场、设备共享、长程记忆或通用文档 IDE。
- 不重建 Agent 会话、取消、任务恢复或消息队列；不为参考项目使用了虚拟列表就立即新增依赖。
- 不改旧运行产物、不自动重放画布操作，不绕过 Reviewer 采用候选。

## Decisions

### 1. 先稳定保存边界，再更新展示

先实现编辑版本与媒体生命周期，再调整选材／节点和协作界面。旧视觉变更中未完成的实机检查仍按原记录保留，本次不能通过更新任务数量把它们自动算成完成。

不先全面重写样式或拆 App：现有组件具备主要职责，新增抽取仅用于共享编辑保存边界或阅读清晰度。

### 2. 编辑版本校验放在现有保存入口

在桌面读取的可编辑来源和画布快照中附带读取签名；表示“文件不存在”的基准与“未提供版本校验”明确区分。受限 IPC 将基准传入原 Python 保存入口，在现有相关运行锁保护下重新读取、比较、写入，不能在拿锁前完成比较后无保护覆盖。

首次导入或新修订目录继续沿用既有显式创建规则；程序内部生成产物不统一加编辑版本字段。旧 CLI 制作流程不因桌面编辑字段变成强制迁移。

冲突时返回稳定的冲突类型与简短说明，前端保留草稿和当前上下文。提供“重新读取”并在确有未保存编辑时明确确认放弃草稿，不提供默认强制覆盖或自动修复。

选择内容签名而非全项目递增版本，避免一次无关文件保存使整个项目失效；沿用已有签名工具，不建立通用依赖图。

### 3. 唯一临时文件与保存串行

`io.py::write_json` 在目标同目录使用唯一临时文件、可靠关闭、原子替换和有限清理，继续发布既有产物事件。该调整防止临时名竞争，不声称提供断电事务或替代业务锁。

前端按当前编辑对象串行提交保存，保存请求捕获项目、运行、对象、基准与草稿版本。响应只确认本次提交版本；用户已继续输入时，不清除新的 dirty 状态。切项目、切运行与关闭应用在原入口等待保存队列；失败留在当前对象，除非用户明确选择放弃修改。

不为每个组件增加不同保存协议，也不建立全局通用状态机。

### 4. 媒体采用短小的租用／释放合同

扩展现有 `media` IPC 与 `MediaFiles`：授权后按规范路径复用资源记录，为每次使用提供独立租约身份；释放一个租约不得影响其他使用者。最后一个使用者释放时回收 token 映射，而不清除原文件授权或删除文件。释放仅接受本次已发出的租约身份，不增加按任意路径清理能力。

`Media.tsx` 的 effect 释放与 acquisition 配对；请求完成时组件若已销毁，应立即释放返回租约，不能只跳过 setState。主进程在对应 renderer 销毁时清理其剩余租约。项目切换不无条件清空全局授权，以免仍挂载的其他视图失效；由视图生命周期释放访问资源。

保留自定义协议和 Range 响应，不改为整段 Blob 下载。文件替换沿用实际产物版本／引用签名刷新，不能复用旧结果冒充新版本。媒体错误只报告已知加载失败，不把 token 积累当作旧视频错误的已证实根因。

### 5. 管理页与选材面板共用数据

保留 MaterialLibrary 的主动导入和去重；管理使用现有完整书架，从输入区进入时以选材面板承接同一记录。取消不变更输入，确认后添加漫画并返回原草稿；整本继续选页和按需加载。过滤只覆盖整本与单页，不增加音视频资源库或空文件夹导航。

首页使用固定输入工具行，已有保存位置与当前项目关系清楚显示。成片库维持只展示视频记录，并沿用原所属项目打开逻辑。

### 6. 节点上下文编辑与已有候选

普通节点保持媒体／简短状态；选中对象显示就近操作，长脚本和对白使用现有详情区。编辑区标明对象与来源，保存、修订执行与查看审查分开。单阶段运行仍使用原命令，不增加节点专用生成后端。

从现有候选、选定记录及审查文件生成历史预览。浏览只读；若已有正式采用入口不足，增加受限操作复用原候选选择与来源签名检查，不允许 UI 任意改生产计划。来源不匹配、审查未通过或会混用已提交视频时阻止直接采用，走原显式修订运行。

节点搜索基于已加载画布模型，点击展开必要分组并走已有定位与回执，不扫描整书或进行模型搜索。

### 7. 多 Agent 可见性由真实任务数据提供

沿用 CreativeTimeline、CreativeComposer 和既有 activities／turn／block／pending_requests。普通正文连续，工具参数默认折叠，阶段卡给出短结论与必要操作；协作详情按轮次展示 Creator 与 Reviewer，并支持产物定位。

送达模式采用现有引导／后续要求语义，队列条显示真实接收和撤回状态。权限取值不变，界面不把编辑或选中误当成付费授权；停止语义继续区分本地进程和远端任务。

不新建子 Agent 聊天服务；协作详情可用现有右侧详情或小型面板实现，返回保留阅读位置。公开说明与审查依据不等同于内部思考，不新增内部推理展示。

### 8. 设置与性能保持最小范围

设置整理现有本机环境，增加只读版本信息分类；类别少时保持简单，不创建待实现的模型／账户导航。保持白色系统字体、可调整无阴影分栏、焦点管理和减少动态效果。

流式路径已存在逐批事件 reduce 中重复复制完整 conversation 的开销，允许改为每批一次克隆并保持原事件身份／顺序规则。先用已有长会话对比实际渲染，不调整传输协议。虚拟列表在本轮范围之外，若仍有性能问题另行提案。

## Risks / Trade-offs

### 用户追加：开源组件局部接入

沿用 React Flow。使用 Radix Dialog／Dropdown Menu 编写本地维护的 shadcn/ui 风格基础组件，承接选材和引用菜单，继续使用项目视觉变量。assistant-ui 使用 ExternalStoreRuntime 读取现有消息、Thread Viewport 处理阅读滚动；不使用云端服务、默认模型适配、前端工具执行或其队列。现有专业协作卡片、分支、停止和持久化不迁移。react-resizable-panels 暂不引入，已有尺寸和折叠逻辑保持。

接入只影响前端，不新增模型请求；保留旧验收欠项，并分别记录本轮本地验证结果。

- [签名检查与写入之间竞争] → 同一现有锁范围内比较与写入；只读检查不能代替写入临界区。
- [旧保存响应清空新草稿] → 保存捕获编辑版本，响应仅确认该版本；切换先 flush。
- [释放媒体导致另一个播放器失效] → 独立租约、引用计数；无使用者时才清理，不全项目清空。
- [候选采用混用历史产物] → 来源签名、审查与已有修订流程共同约束，预览不改选定记录。
- [折叠工具过程隐藏错误或提问] → 问题、恢复与失败短说明常驻，只有参数和依据折叠。
- [合并事件引入丢增量或跨分支污染] → 保留现有事件过滤，针对重复事件、旧轮和结束 flush 使用少量已有检查。

## Migration Plan

1. 记录现有示例与保存／媒体入口，实施唯一临时文件、编辑校验和保存完成边界。
2. 扩展同一桌面版本的媒体获取／释放协议，更新主进程、preload 与 React 使用者；没有使用者版本混用承诺。
3. 在同一工作流上调整素材、节点、候选和设置，再完成协作与队列展示。
4. 运行必要类型检查、构建和关键回归；用独立本地项目完成客户端检查。默认不调用付费模型，不改实际用户配置。

无全库数据迁移；读取旧运行时现场计算编辑基准，已有磁盘产物保持不变。若某一批有问题，回退该批代码并保留用户新产物，不删除历史结果或覆盖为旧快照。最终只在实际验收完成后勾选对应任务并更新状态。
