## Why

逐格将漫画重绘为视频首帧，会把动作高潮、反应或结束瞬间错误地固定为镜头起点，也缺少跨格的镜头组织与节奏安排。MangaWeaver 需要以 Manga2Animate 的三阶段实现为基础，建立能分类、编排并生成静态与动作镜头的最小可用框架。

## What Changes

- 按已选定的 `src/mangaweaver/` 结构建立本地 Python 包与 CLI，支持预处理、规划、生成分别执行。
- 参考原项目迁入分格、OCR、角色描述、脚本与分镜 Creator／Reviewer、模型调用及文件式运行记录。
- 增加镜头编排 Creator／Reviewer：跨漫画格识别事件，分类 `static`／`action`，输出有来源映射的镜头清单。
- 对动作镜头增加演出 Creator／Reviewer，明确入点、漫画关键瞬间、强调、停顿、出点和关键帧时间安排。
- 静态镜头使用单张分镜首帧；动作镜头暂按相邻关键帧构建首尾帧生成段。视频后端指定 MiniMax H3，实施前先核实实际入口能力，不能以参考图模式冒充端点控制。
- 保留有限轮次反馈、候选选择、任务查询、人工可检查产物与简单剪辑；失败明确报出，不实现复杂回退、自动重规划或通用依赖系统。

## Capabilities

### New Capabilities

- `local-workflow`: 本地包与分阶段命令、输入与运行目录、配置、结果记录和显式恢复。
- `manga-preprocessing`: 漫画分格、阅读顺序、OCR、角色描述及预处理结果复用。
- `shot-planning`: 原作脚本、跨格镜头分类与编排、动作镜头演出、视觉分镜与第二阶段反馈。
- `video-production`: MiniMax H3 能力核实、静态与动作任务、候选审查、段内连接及镜头剪辑导出。

### Modified Capabilities

无。当前项目尚无已发布代码或主规范。

## Impact

- 新增 Python 包、提示词、示例与运行说明；现有项目目标和架构文档继续作为背景依据。
- 接入 Gemini 和 MiniMax H3；预处理与剪辑依赖按参考实现及实际需要配置。
- 实际账号权限和 H3 端点能力是第三阶段的外部依赖；若能力不符，保留可执行的上游规划并说明缺口，不自动换模型。
- 不包含 Web 服务、模型训练、历史 latent 续写、完整配音、复杂运维设施或大规模测试。
