# agent-streaming-conversations Specification

## Purpose
让用户在 Agent 处理过程中逐步看到真实回复，并在同一轮中理解说明、工具和结果的先后关系。部分输出、完成和中断具有明确区别，重开项目能够恢复真实记录，不能用预制文字动画代替模型流式能力。

## Requirements

### Requirement: 真实的模型文字增量
系统 MUST 在配置渠道返回增量时及时显示可公开的回复文字，不能等完整响应后再模拟逐字显示。界面 MUST 不展示原始 JSON、密钥或隐藏思考过程。渠道不支持流式或请求失败时 MUST 明确说明，不能自动更换模型、切换供应商或将非流式响应标为流式。

#### Scenario: 首次回复尚未结束
- **WHEN** 模型已返回公开文字增量但本次响应仍在继续
- **THEN** 用户看到持续增长的同一回复及生成中状态，而非只有固定的正在理解提示

### Requirement: 完整且有序的对话轮次
系统 MUST 将同一轮的公开说明、工具调用、进展、结果和最终回复按实际顺序组织，关联稳定会话、分支、轮次和内容块身份。刷新、事件重放或子任务事件交错 MUST 不重复插入内容或合并到另一条回复。

#### Scenario: 读取后继续委派
- **WHEN** Agent 先读取规划，再委派编排，最后解释结果
- **THEN** 同一轮依次呈现说明、读取工具、专业委派和结果回复，相关任务卡位于实际委派处

### Requirement: 中断与恢复不伪造完成
停止或断流时系统 MUST 保留已接收并保存的部分文字，明确区分用户停止、执行失败和正常完成。重开只恢复记录，MUST 不自动重发请求或执行残缺动作。重试 MUST 有独立尝试身份且不重复拼接前次输出。

#### Scenario: 回复中途停止
- **WHEN** 用户在文字尚未输出完时停止并重开项目
- **THEN** 部分文字仍可查看并标为中断，用户明确继续后才开始新尝试，不展示虚构结尾
