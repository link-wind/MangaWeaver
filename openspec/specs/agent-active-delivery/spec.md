# agent-active-delivery Specification

## Purpose
让用户补充、后续要求和专业任务提问进入正确的活动会话，而不是只在界面保存一条待办。送达与意图继续分开，执行在安全边界进行，接收、撤回和恢复都保持明确归属及原有授权范围。

## Requirements

### Requirement: 当前引导进入正确会话
当前引导 MUST 绑定发送时的分支、父任务、相关子任务、页面和版本，在当前调用保存后、下一项受影响动作前接收。系统 MUST 显示待处理与已接收的区别；问题回答后继续原目标，只有内容修改进入修订路径，不能将新引导注入已发出的模型请求。

#### Scenario: 专业任务运行中补充要求
- **WHEN** 用户对当前编排镜头补充节奏要求
- **THEN** 引导进入对应专业任务的下一安全边界，保留原目标和已完成结果，不并行启动另一套制作

### Requirement: 后续要求独立且有序
后续要求 MUST 在当前任务正常完成后按接收顺序建立独立轮次和任务身份，不覆盖当前目标。未接收可撤回；接收后只能通过明确中断或修订处理。重复递送 MUST 不重复执行；超出目标或授权时等待决定。

#### Scenario: 编排之后处理下一页
- **WHEN** 用户已允许两页规划并要求当前页完成后处理下一页
- **THEN** 当前任务完成后开始独立的下一页任务，保留来源要求及两页各自状态，不开始生图

### Requirement: 停止与提问的路由明确
明确停止 MUST 优先于排队消息；父子提问的答案 MUST 通过问题身份回到原会话。切分支、目标变化或问题过期时 MUST 阻止误投并说明原因。停止、失败、等待用户和重开 MUST 不自动消费后续要求。

#### Scenario: 切分支后回答旧问题
- **WHEN** 用户正在另一分支并尝试回答原专业任务问题
- **THEN** 系统显示原问题归属并要求回到对应分支处理，不将答案应用到当前分支的同名镜头
