# agent-task-workflow Specification

## Purpose
让创作对话与手动阶段操作共享可追踪的制作任务，明确总 Agent、专业 Creator／Reviewer 和执行工具之间的职责、交接与反馈，使用户能够理解推进、修改和恢复的真实状态。

## Requirements

### Requirement: 统一目标与任务身份
系统 MUST 为明确的制作请求保存稳定任务身份、入口、目标页面与运行版本、目标对象、制作终点、授权范围及父子任务关联。对话与手动阶段操作 MUST 使用一致的任务状态和执行结果；手动阶段操作 MUST 保留只执行所选阶段的行为，缺少前置结果时明确提示，不隐式执行其他付费阶段。

#### Scenario: 对话完成镜头规划
- **WHEN** 用户允许规划并要求完成当前页镜头编排
- **THEN** 系统在同一父任务下完成必要来源脚本与编排子任务，通过审查后停在编排终点，不开始生图

#### Scenario: 手动入口缺少前置
- **WHEN** 用户点击关键画面阶段，但缺少有效镜头编排
- **THEN** 系统记录该阶段任务及明确的前置阻塞，提供前往所需阶段的操作，不自动扩大制作范围

### Requirement: 专业协作可追踪
系统 MUST 区分总 Agent 的委派、Creator 的提交、Reviewer 的判断和工具执行，关联真实目标、轮次、产物和审查记录。专业任务 MUST 仅在必要审查通过后完成，总 Agent MUST 不覆盖专业审查结论。确定性处理 MUST 不伪装为推理 Agent。

#### Scenario: 编排退回修订
- **WHEN** Reviewer 判定第二镜头节奏不合理
- **THEN** 系统记录问题位置、依据、修订建议与接收该反馈的 Creator，随后提交的新候选关联同一任务的新轮次，审查通过后才进入后续阶段

#### Scenario: 专业问题需要上游修改
- **WHEN** 关键画面审查指出错误来自来源脚本
- **THEN** 系统沿已有反馈路由记录上游退回与受影响目标，不把该问题当作下载失败或无条件重画

### Requirement: 在授权终点内连续推进
系统 MUST 在已明确的目标和授权内推进通过审查的依赖阶段。内部工具决策步数边界 MUST 保留任务并可在当前活动制作中续接，不要求用户为该内部边界重复发送继续；业务修订轮次 MUST 仍有限。系统 MUST 在信息不足、超出授权、修订耗尽或执行失败时给出明确暂停原因和下一步。阶段检查暂停与任务终点完成 MUST 可区分。

#### Scenario: 内部动作批次结束
- **WHEN** 当前请求达到内部动作批次上限，但目标未完成、未停止且未超出授权
- **THEN** 系统保持同一任务身份和业务修订计数，在活动客户端中续接剩余步骤，不宣称完成、不重新授权、不无限重复无进展操作

#### Scenario: 内容修订达到上限
- **WHEN** 同一专业任务在有限修订后仍未通过
- **THEN** 系统保留候选和最后审查问题并等待用户处理，不靠内部续接重置轮次或绕过审查

### Requirement: 明确区分内容退回和执行错误
系统 MUST 将内容不通过、传输或执行失败、等待用户决定分别处理。内容反馈 MUST 进入已有专业修订路径；执行失败 MUST 保留检查点和可用恢复操作，不自动改写已通过内容、不自动换模型。视频内容不通过后，额外付费重生成 MUST 有明确范围和用户启动动作。

#### Scenario: 视频下载失败
- **WHEN** 已存在远端任务标识但下载失败
- **THEN** 系统展示恢复原任务查询或下载的入口，不启动新的 Creator 内容轮次或重新提交视频

#### Scenario: 视频质量不通过
- **WHEN** 视频 Reviewer 判定候选对白或动作存在阻断问题
- **THEN** 系统展示实际问题和保留候选，说明建议修订目标，等待用户明确启动需要新增付费生成的操作

### Requirement: 运行中提交待处理修改
系统 MUST 允许运行期间提交并保存修改要求，绑定提交时的页面、目标对象和运行版本，明确显示待处理；提交 MUST 不修改正在执行步骤的输入。系统 MUST 在完成当前模型调用并保存检查点后、启动下一项受影响工作之前处理修改，必要时创建修订运行。等待修改 MUST 可撤回；目标或版本冲突时 MUST 请求用户决定，不把修改应用到当前恰好选中的另一页。

#### Scenario: 生图时提交镜头修改
- **WHEN** 第一张图生成期间用户提交第二镜头的修改
- **THEN** 当前调用继续保存真实结果，修改显示为待处理，在下一项受影响工作开始前处理，不同时启动另一套制作

#### Scenario: 切页后保留修改对象
- **WHEN** 用户提交第十二页镜头修改后切到第十三页
- **THEN** 修改仍绑定第十二页，不修改第十三页；若第十二页版本已改变则提示处理冲突

### Requirement: 真实终态与显式恢复
系统 MUST 根据任务的明确结果及有效产物更新状态，不因出现下一阶段事件推断审查通过。停止 MUST 阻止后续阶段、批次和待处理修改自动启动。重开 MUST 恢复显示但不自动制作；明确恢复 MUST 使用已保存检查点与远端任务身份，提交结果不明时要求核查，不重复付费提交。

#### Scenario: 停止并重开
- **WHEN** 用户停止制作并重开项目，任务还有待处理修改及远端视频
- **THEN** 界面恢复中断状态、修改和远端标识，说明本地停止不等于远端取消，只有明确恢复后才继续

#### Scenario: 阶段事件交错
- **WHEN** 多个视频候选已提交并出现其他阶段的进度事件
- **THEN** 尚未得到结果的候选仍显示实际等待状态，不因事件切换标为完成
