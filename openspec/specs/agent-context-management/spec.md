# agent-context-management Specification

## Purpose
让长对话与专业会话在模型上下文预算内保持关键约束和任务连续性，用户可以理解用量与摘要的作用。摘要不能取代原始产物、专业审查和授权记录，也不能因为省略旧消息而遗忘未完成的要求。

## Requirements

### Requirement: 上下文预算透明
系统 MUST 分别记录或估算活动会话和专业会话的上下文用量，区分实际供应商用量与本地估算；模型容量未知时 MUST 明确标注并使用显式配置预算，不能虚构容量、费用或准确百分比。界面 MUST 提供简短状态及按需展开的用量详情。

#### Scenario: 渠道未返回 token 用量
- **WHEN** 当前渠道没有可靠用量或模型容量信息
- **THEN** 界面将本地估算与未知容量明确区分，不把推测数字显示为实际账单

### Requirement: 摘要保留任务必需事实
压缩 MUST 保留或明确引用用户目标、原作约束、配色／对白决定、授权边界、活动任务、未解决问题、待处理引导、产物版本及远端任务标识。每份摘要 MUST 可追溯到原会话范围，原记录保持可查看；不能把未审查候选、建议或中断动作总结成已完成结果。

#### Scenario: 长对话后仍有拒绝和待办
- **WHEN** 上下文压缩发生在专业审查拒绝且还有后续要求时
- **THEN** 拒绝、问题依据、待办归属和授权仍被保留，后续不会因为摘要遗漏而跳过审查或重交视频

### Requirement: 压缩触发与失败可控
系统 MUST 支持活动轮次内按预算压缩及用户明确发起压缩，显示开始、完成或失败。仅浏览、切分支、重开项目 MUST 不调用模型压缩。失败时 MUST 保留原记录并明确暂停无法容纳的请求，不静默丢弃关键上下文、换模型或无限重试。

#### Scenario: 打开长会话
- **WHEN** 用户只打开一个较长的历史会话
- **THEN** 系统恢复历史及已有摘要，不自动产生压缩调用或制作费用
