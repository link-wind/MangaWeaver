# book-workspace Specification

## Purpose
让整本漫画的管理、选页与单页创作在同一个项目中清楚分工。用户可以查看真实页面及各页进度，进入单页画布编辑，并在后台制作期间保持自己的浏览位置与对话目标。

## Requirements

### Requirement: 全书总览与显式选页

客户端 MUST 提供固定布局的全书缩略图总览，支持文件页序跳转、状态筛选、分批加载与多选。浏览和选择 MUST 不调用模型或创建页面运行；只有明确制作才创建必要运行。

#### Scenario: 选择和打开未制作页面
- **WHEN** 用户选择若干页并打开其中一页
- **THEN** 只显示该页原图，不提交制作；保留其余已选页，提供明确批量制作入口。

### Requirement: 单页隔离和取景恢复

页面画布 MUST 只展示当前页产物，支持前后页与跳页；每页的视口、折叠、节点位置和选择 MUST 独立保留。

#### Scenario: 切页后返回
- **WHEN** 用户调整第94页取景，打开95页，再返回94页
- **THEN** 恢复94页取景和选择，画布不出现95页节点。

### Requirement: 后台执行和浏览分离

制作 MUST 沿用已有串行任务与停止机制，运行进度 MUST 不自动改变用户查看页。运行中 MUST 允许浏览其他页，同时禁止危险产物修改。

#### Scenario: 后台制作另一页
- **WHEN** 用户查看94页而95页正在制作
- **THEN** 94页保持打开，紧凑运行入口标明95页；用户可主动定位。

### Requirement: 稳定的页面对话目标

项目对话 MUST 保留页码归属并支持当前页／全书筛选；非空草稿与手动引用 MUST 在切页后保持原目标。

#### Scenario: 草稿跨页
- **WHEN** 用户在94页起草要求后切到95页并发送
- **THEN** 明确显示并提交94页目标，不能误指向95页。
