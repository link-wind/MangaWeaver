# agent-collaboration-timeline Specification

## Purpose
在简洁的右侧创作栏中按实际发生顺序展示用户要求、总 Agent 协调、专业协作和需要处理的问题，让用户能够从任务找到画布产物，也能从产物追溯创作与审查过程。

## Requirements

### Requirement: 对话与任务共用时间线
右侧 MUST 将用户消息、总 Agent 回复和任务卡片按实际顺序组织，并保持消息与任务的关联，不再把所有运行日志单独堆到对话末尾。来自阶段按钮的操作 MUST 作为对应操作记录展示，不伪造用户自然语言发言。重开或刷新 MUST 不重复插入相同任务或打乱消息顺序。

#### Scenario: 连续两次要求
- **WHEN** 用户完成一次编排后又提出镜头修改
- **THEN** 第二次要求及其修订任务位于第一次任务之后，可分别查看各自过程和结果

### Requirement: 简洁呈现真实专业角色
任务卡片 MUST 默认展示任务名称、页面或目标、当前负责角色、状态和短摘要，详细内容折叠。展开 MUST 能查看实际 Creator 提交、Reviewer 结论、修订轮次、上游退回及产物引用；工具处理使用明确工具名称。系统 MUST 不展示虚构 Agent 对话、未经记录的审查结论或冗长模型思考过程。

#### Scenario: 查看编排协作
- **WHEN** 用户展开已通过的镜头编排卡片
- **THEN** 用户能看到对应 Creator 产物、Reviewer 问题与依据、实际修订和最终通过记录；复用旧产物明确标为复用

### Requirement: 当前进度与下一步清楚可用
创作栏 MUST 持续展示当前任务、负责角色和明确的执行状态，区分创作、审查、远端生成、下载、等待输入、失败、中断及完成。暂停或失败时 MUST 提供与原因匹配的操作，运行中 MUST 保留停止入口；内部批次续接不展示为需要用户决定的问题。系统 MUST 不以无依据的百分比或剩余时间承诺进度。

#### Scenario: 审查需要较长等待
- **WHEN** 视频生成已结束而 Reviewer 正在审查
- **THEN** 用户看到视频审查中及已完成片段数量，不把该过程显示成视频仍在生成或无状态卡死

#### Scenario: 原任务下载失败
- **WHEN** 任务因下载失败停止
- **THEN** 卡片展示失败位置、保留产物和恢复原下载入口，避免只显示通用的继续按钮

### Requirement: 任务与画布双向定位
任务卡片 MUST 能定位对应页面、镜头、关键画面或成片，并按需展开所属折叠组；节点详情 MUST 能跳到对应任务和审查记录。定位 MUST 使用有效的业务身份和已有完成回执；旧版本与旧运行产物 MUST 明确标识，不能误定位到当前同名节点。

#### Scenario: 定位收起的关键画面
- **WHEN** 用户点击任务卡片的查看关键画面，而所属页面或阶段已折叠
- **THEN** 系统展开正确分支并定位目标，实际完成后才显示定位成功

### Requirement: 简化输入范围与待处理修改
输入区 MUST 显示当前页或选中目标及本次制作范围，避免同时出现含义重叠的阶段、权限和运行控制。已明确授权范围 MUST 可复用；超出范围时展示具体计划并等待决定。运行中提交的修改 MUST 有独立待处理状态、目标和撤回入口，停止后不自动处理。

#### Scenario: 已允许规划但请求生图
- **WHEN** 用户当前仅允许规划并提出生成关键画面的要求
- **THEN** 系统明确列出将新增的生图工作并提供确认操作，不要求用户自行理解隐藏阶段或多处权限开关

#### Scenario: 运行中提交修改
- **WHEN** 用户在制作期间发送目标明确的修改
- **THEN** 时间线立即显示要求及待处理标识；后续显示实际接收、撤回、冲突或修订结果，不提前标为已应用

### Requirement: 旧记录只读兼容
系统 MUST 保留旧会话、审查文件和运行日志的可查看性；历史记录缺少角色或任务身份时 MUST 显示为历史记录，不推测完整协作过程。仅查看历史、恢复布局和切换任务 MUST 不调用模型或自动制作。

#### Scenario: 打开旧成片项目
- **WHEN** 项目只有旧会话、阶段日志和成片，没有新任务身份
- **THEN** 用户仍能查看原记录与成片，历史记录明确标识，系统不补造 Agent 轮次或自动重跑
