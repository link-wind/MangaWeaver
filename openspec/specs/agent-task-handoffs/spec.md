# agent-task-handoffs Specification

## Purpose
让总创作 Agent 与专业 Creator／Reviewer 的协作通过可检查的任务书和回报连接起来，说明目标、可改范围、输入依据和实际结果。用户能够理解专业审查如何驱动修订，而不需要查看冗长提示词或把工具执行误认为 Agent 决策。

## Requirements

### Requirement: 专业委派携带精简任务书
每次专业委派 MUST 关联稳定父子任务与输入版本，明确本次目标、原作及输入引用、允许修改的对象与范围、必须保留的约束、授权及预期输出。专业上下文 MUST 聚焦本阶段所需信息，不依赖完整聊天历史推测任务。输入缺失或目标不明确时 MUST 返回阻塞或待决定，不自行扩大范围。

#### Scenario: 第二镜头节奏修订
- **WHEN** 总 Agent 委派缩短第二镜头停顿
- **THEN** 专业任务书包含该镜头与来源版本、用户要求、需要保留的原作事件和对白、可修改范围及预期产物，不把整页其他镜头都作为可任意重写对象

### Requirement: 专业回报对应真实结果
专业任务 MUST 返回与现有任务状态一致的结果，包含完成摘要、真实产物引用、审查结论和问题依据，以及阻塞或需要上游协调的事项。没有产物或审查尚未通过时 MUST 不声称完成。下一步接收者或建议 MUST 与事实结果区分，不构成额外执行授权；复用结果 MUST 明确标记。

#### Scenario: 专业任务复用结果
- **WHEN** 某阶段复用已通过且输入匹配的产物
- **THEN** 回报标注复用、实际版本与已有审查，不伪造新的 Creator 提交或 Reviewer 调用

#### Scenario: 缺少来源脚本
- **WHEN** 编排专业任务缺少有效来源脚本
- **THEN** 回报具体阻塞和所需输入，不提交虚构编排、不自行绕过阶段前置

### Requirement: 审查和修订沿既有职责交接
系统 MUST 保留总 Agent 协调、Creator 创作、Reviewer 审查的职责边界，沿用已有有限反馈和上游退回机制。Reviewer 的拒绝 MUST 不被总 Agent 改为通过；修订 MUST 关联原问题、接收角色、轮次与新产物。确定性反馈路由 MUST 标为流程交接，不能伪装成额外 Agent 推理或绕过修订上限。

#### Scenario: 编排审查退回
- **WHEN** Reviewer 指出第二镜头对白过密
- **THEN** 系统保存依据并交给编排 Creator 修订，新结果再次审查；时间线显示真实提交、退回和后续结论，不能提前标记通过

#### Scenario: 需要上游处理
- **WHEN** 关键画面审查发现原因为来源脚本识别错误
- **THEN** 回报包含上游目标和问题依据，由既有协调路径在授权范围内处理或等待决定，不任意递归委派新的 Agent

### Requirement: 简洁展示可追溯交接
任务时间线 MUST 简短展示实际负责角色、交接对象、反馈摘要及结果，任务书、完整问题依据和产物引用默认折叠。用户 MUST 能沿任务和引用找到对应产物、审查与画布位置。展示 MUST 来源于实际执行或复用记录，不生成虚构角色互聊、不暴露模型思考过程，也不把分格、下载、剪辑等确定性工具包装成 Agent。

#### Scenario: 展开专业任务
- **WHEN** 用户展开已完成的编排任务
- **THEN** 用户能查看本次任务书、实际 Creator／Reviewer 交接、修订问题与产物版本，界面不会补造未发生的模型调用
